# ボランティアシフト配置ツール

場所×時間帯のシフト枠に、ボランティアと職員を割り当てるためのツールです。
Google Apps Script（GAS）で動き、データはスプレッドシートに入ります。

> ボランティアと職員から「入れる時間帯」を先に集め、場所×時間帯の枠へ、**ボランティア優先で**割り当てる。足りない枠を職員が埋める。

**利用者にGoogleアカウントは要りません。** 配布したURL（QRコード）を開くだけで応募できます。

## はじめの設定

初回だけ、次の4ステップを行います。

### 1. コードをスプレッドシートへ入れる

このプロジェクトはスプレッドシートにコンテナバインドしたGASプロジェクトです。

```bash
clasp push
```

### 2. `setup()` を実行する

スクリプトエディタで関数 `setup()` を選んで実行します。初回は認可（アクセスを許可）を求められます。

- 必要なシートとヘッダーが作られます
- `_config` に既定値が入り、閲覧トークンが発行されます
- 日付・時刻の列が「書式なしテキスト」になります（日付型に化けるのを防ぐため）
- `_config` と `_log` は非表示になります

**何度実行しても安全**です。既にある値は上書きしません。

### 3. Webアプリとしてデプロイする

エディタの「デプロイ」→「新しいデプロイ」→ 種類は **ウェブアプリ**。設定は次のとおりにします。

| 項目 | 値 |
|---|---|
| 次のユーザーとして実行 | **自分** |
| アクセスできるユーザー | **全員（匿名ユーザーを含む）** |

この組み合わせでないと、ボランティアがGoogleアカウント無しで応募できません。閲覧者にスプレッドシートの権限は渡りません。

> 2回目以降にコードを直したときは、「新しいデプロイ」ではなく**既存デプロイの「編集」→ バージョンを「新バージョン」**にします。URLが変わらないので、配ったQRコードが無効になりません。

#### ⚠️ アクセス設定は `appsscript.json` では変わりません

`appsscript.json` にも同じ設定（`ANYONE_ANONYMOUS`）が書いてありますが、**これが効くのは新しくデプロイを作るときだけ**です。既にあるデプロイのアクセス設定は、作った時点のもので固定されます。`clasp push` や `clasp deploy` では変わりません。

**ログインを求められる場合は、「デプロイを管理」→ 鉛筆アイコン →「アクセスできるユーザー」を「全員」に変更**してください。URLは変わりません。

確認は**シークレットウィンドウ**（ログアウト状態）で行います。ふだんのウィンドウでは自分がログイン済みのため、切り分けになりません。

### 4. URLを取得する

スクリプトエディタで **`showViewUrl()`** を実行し、実行ログに出る4つのURLを控えます。

```
配置表・閲覧用（見るだけ）: https://script.google.com/.../exec?t=xxxxxxxx
配置表・管理用（枠と割り当てを編集できる）: ...?t=xxxxxxxx&view=admin
応募フォーム（QRコードにするのはこれ）: ...?t=xxxxxxxx&view=entry
代理入力（管理者だけが使う）: ...?t=xxxxxxxx&view=entry&proxy=1
閲覧トークン: xxxxxxxx
```

**必ずこのURLを使ってください。** デプロイ画面に出るURLをそのまま開くと `?t=…` が付いておらず、「このURLでは開けません」と表示されます。

出力されたURLの末尾が `/dev` になっている場合は、それは開発者専用のテストURLです。配布にはデプロイ画面の `/exec` のURLに `?t=…` 以降を付けたものを使ってください。

## 4つのURL

| URL | 誰に渡すか | できること |
|---|---|---|
| `?t=…` | 関係者・見るだけの人 | 配置表の**閲覧のみ**。管理操作のボタンは出ません |
| `?t=…&view=admin` | 管理する人 | 枠の作成・割り当て・場所の管理 |
| `?t=…&view=entry` | **ボランティア全員（QRコード）** | 自分の入れる時間帯を登録する |
| `?t=…&view=entry&proxy=1` | 管理者 | 他の人の代わりに時間帯を登録する（種別も選べる） |

日付を指定して開くこともできます: `?t=…&d=2026-08-10`

### ⚠️ URLの扱いについて

**このツールにログイン機能はありません。** 保護はURLに含まれるトークン1段階だけです。

- URLを知っている人は**誰でも枠の作成・編集・割り当てができます**
- ボランティアに配るのは応募フォームのURLですが、そこからトークンは見えてしまいます
- **閲覧用と管理用でURLを分けていますが、保護ではありません。** トークンは共通で、閲覧URLに `&view=admin` を足すだけで管理画面が開きます。誤操作を防ぐための画面の分離です
- 誰が操作したかの記名は行いません。`_log` の操作者列には `(管理画面)` と記録されます

これは「単発のボランティアにログインを求めない」ことを優先した上での判断です。URLが広く漏れてしまった場合は、スクリプトエディタで **`regenerateViewToken()`** を実行してください。トークンが作り直され、**以前のURL・QRコードはすべて無効**になります（配り直しが必要です）。

## 使う順番

### ① 場所を登録する

**管理用URL**（`&view=admin`）を開く → 「場所」ボタン。

表示順と場所名を入れて保存します。使わなくなった場所は「表示」のチェックを外します（**行は消えません**。過去の配置表が読めなくなるためです）。

### ② 枠を作る（先に作らなくても構いません）

枠は「どの場所の、何時から何時までに、何人必要か」です。

**普段は作る必要がありません。** 枠を1つも作っていない場所には、`_config` の既定時間帯（初期値 **10:00〜17:00**）の枠が**破線で最初から表示されます**。そこに人を入れれば、その時点で枠が本物になります。

```
A地点  ┌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌┐   ← 破線＝まだシートに無い「既定の枠」
       ╎ 10:00–17:00      ╎      タップして人を入れると実体になる
       ╎ 既定の枠         ╎
       └╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌┘
```

時間帯は `_config` の `default_slot_start` / `default_slot_end` で変えられます。開始か終了を空にすると、この表示は出なくなります。

先に枠を作るのは、**「まだ誰も入っていない枠」を用意したいとき**です。「土曜の10時から3名必要」と決まっているなら先に枠を作っておくと、不足が画面に残ります。管理画面の「**既定の枠**」ボタンから、破線で出ている枠をまとめてシート上の枠にできます。

**同じ枠（日付・場所・開始・終了が一致）が既にあれば作られません。** 同じ操作を2回しても増えません。

作った枠の場所や時間を直したいときは、枠をタップすると出るパネルの上部から変更・削除できます。

### ③ 応募を集める

応募フォームのURLをQRコードにして配ります。ボランティアは名前・連絡先・入れる日と時間帯を入れて送信するだけです。

```
入れる日と時間帯
┌─ 8月10日(土) ──────────┐
│ [10:00] 〜 [12:00]    × │
│ [＋ 時間帯を追加] [終日OK] │
└─────────────────────────┘
[＋ 日付を追加]
```

- **複数の日をまとめて登録できます。** 「＋ 日付を追加」を押すと、**直前の日と同じ時間帯**が入った状態で翌日のブロックが増えます。同じ時間で通う人は日付を足すだけで済みます
- 日によって都合が違う場合は、その日の時間帯だけ直してください
- 時刻は**時と分を直接入力**します（プルダウンではありません）
- 「終日OK」ボタンで表示時間帯を一括入力できます（日付ごと）
- 途中で抜ける日は、時間帯を分けて追加できます（例: 10:00〜12:00 と 15:00〜17:00）
- 同じ人が何度送っても、**申告した時間が減ることはありません**（前の申告と合算されます）
- 職員は登録しておけば、時間帯を申告しなくても既定の勤務時間帯（`_config`）で扱われます

紙で集めた分は、代理入力URL（`&proxy=1`）から管理者が入力します。

### ④ 割り当てる

配置表 → **管理用URL**を開きます。ここから2通りの入れ方があります。

#### 空いているところをタップする（枠がまだ無いとき）

```
【A地点の空いているところをタップ】
   ↓
人を選ぶ    鈴木（申告 09:00–12:00）
   ↓
時間を決める  09:00 〜 12:00   ← 初期値はその人の申告時間。変えられます
   ↓
【この内容で登録】→ 09:00–12:00 の枠ができて、鈴木さんが入る
```

**枠を先に作る必要はありません。** 人と時間を選ぶだけで枠ができます。同じ日付・場所・時間の枠が既にあれば、新しく作らずにその枠に入ります。

#### すでにある枠をタップする

枠に入っている人と、その枠に入れる候補者が出ます。名前をタップすれば、**枠の時間そのまま**で入ります。

枠と違う時間で入れたいときは、パネル下の**「時間を指定して入れる」**から。指定した時間の枠が別にできて、配置表では同じ場所の2段目に並びます。「一部の時間のみ可用」の人を選んだときも同じで、その人が入れる時間の枠ができます。

候補者は**ボランティアが上、職員が下**に並びます。同じ種別の中では、その日の割り当てが少ない人が上に来ます。まずボランティアで埋めて、残りを職員で埋める、という順番で作業できます。

## 画面の説明

### 配置表

縦が場所、横が時間のタイムラインです。枠のブロックには次が出ます。

```
10:00–11:30
2名
田中、佐藤（職）
```

- 2行目 … 割り当て済みの人数（誰も入っていなければ「未割当」）
- 3行目 … 割り当て済みの人の名前（「（職）」が職員）

**必要人数は表示しません。** 何名必要かは場所ごとに決めて運用してください。

日付は前後の矢印、カレンダー、「今日」ボタンで切り替えます。

### 管理画面（`&view=admin`）

管理用URLを開くと、上部に操作の列が出ます。**モードの切り替えやログインはありません。** 閲覧用URLでは同じ画面が読み取り専用になり、枠をタップしても何も起きません。

タップした場所で操作が決まります。

| タップした場所 | 開くもの |
|---|---|
| 空いているところ | 人を選んで時間を決める画面（登録すると枠ができる） |
| すでにある枠 | **枠のパネル**（上で場所・時間を編集、下で人の追加・解除） |

### 割り当てパネル

```
[ A地点 10:00–11:30 ]

場所  [A地点        ▾]
時間  [10:00] 〜 [11:30]
メモ  [                ]
  [この枠を削除] [枠を保存]
──────────────────────
割り当て済み (2)
  田中   ボランティア   [解除]
  佐藤   職員          [解除]

割り当て可能 (3)
  ボランティア
    鈴木   割当なし      ＋
    高橋   1時間         ＋
  職員
    伊藤   2時間         ＋

▶ 一部の時間のみ可用 (1)

[ 時間を指定して入れる ]
```

- 名前をタップすると、**枠の時間そのまま**で割り当てられます。すぐ横の「本日の割当」は、その日にその人が入っている合計時間です
- **同じ時間に別の場所へ入っている人は候補に出ません**（ダブルブッキング防止）。連続する枠（10:00–11:00 と 11:00–12:00）は重ならない扱いなので、同じ人を続けて入れられます
- 「一部の時間のみ可用」は、枠の一部にしか入れない人です。選ぶと**その人が入れる時間の枠**を作ります
- 「時間を指定して入れる」は、枠と違う時間で人を入れたいときに使います。指定した時間の枠が別にできます
- **パネルの上で、枠の場所・時間を直せます。** 「枠を保存」で反映、「この枠を削除」で枠ごと消えます（割り当てがある枠は削除できません）
- **人数の上限はありません。** 何名必要かは場所ごとに決めて運用してください

### 人ごとの一覧（配置表の下半分）

配置表は上下2段になっています。**上が「場所ごと」、下が「人ごと」**です。同じ日を2つの見方で並べているので、上で枠の埋まり具合を見ながら、下で空いている人を探せます。

```
             10:00      12:00      14:00      16:00
鈴木  空き     ░░░░░░░░░░░░░░░░░░░  ░░░░░░░░░░░░░
高橋  2時間    ░░░░░░░░░░[A地点]░░░░░░░░░░░░░░░░░░
伊藤（職員）   ┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈
```

- **薄いグレーの帯**が「入れる」と申告された時間、**青い帯**が割り当て済みの時間（場所名入り）です
- **破線の帯**は職員の既定勤務時間帯です（本人が申告したものではありません）
- **まだ割り当ての無い人が上**に並びます。「あと誰に頼めるか」を探すための順番です
- 上部に、その日の登録人数・まだ割り当ての無い人数・割り当て件数・時間の合計が出ます
- 申告の外に割り当てられている区間は**赤**で表示されます（応募を取り下げた人が割り当てられたままなど）
- 管理用URLでは、**青い帯をタップすると割り当てを解除できます**（確認画面が出ます）

## スプレッドシートで直接やること

画面から操作できないことは、シートを直接編集します。**シートそのものが管理画面**です。

| やりたいこと | シート | 操作 |
|---|---|---|
| 連絡先を調べる | `people` | `contact` 列を見る。**画面には一切出ません** |
| 職員を登録する | `people` | `type` を `staff`、`is_recurring` を `TRUE` にする |
| 継続参加者を候補に出し続ける | `people` | `is_recurring` を `TRUE` にする |
| 並べ替えのふりがなを入れる | `people` | `kana` 列 |
| 同じ人の重複を名寄せする | `people` | 残さない側の `merged_into` に、残す側の `id` を書く（**行は消さない**） |
| 誰が何をしたか調べる | `_log` | 非表示シート。タブを右クリック →「非表示のシート」から表示 |
| 動作設定を変える | `_config` | 下記 |

### 気をつけること

- **日付は `YYYY-MM-DD`、時刻は `HH:mm` の文字列**です。セルの書式は `setup()` が「書式なしテキスト」にしています。書式を変えると動かなくなります
- `id` 列は書き換えないでください。行の削除も、割り当てや過去の記録から参照されているため避けてください（`places` と `people` は「使わない」印で運用します）

## `_config` の設定項目

非表示シートです（タブを右クリック →「非表示のシート」から表示）。

| キー | 既定値 | 説明 |
|---|---|---|
| `view_token` | 自動生成 | 閲覧URLのトークン。**手で書き換えない** |
| `day_start` | `10:00` | 配置表・応募フォームの表示開始時刻 |
| `day_end` | `17:00` | 同、終了時刻 |
| `slot_unit_minutes` | `10` | 時刻選択の刻み（分） |
| `default_slot_start` | `10:00` | **既定の枠**の開始。枠が無い場所に破線で表示されます。空にすると表示しません |
| `default_slot_end` | `17:00` | 同、終了 |
| `staff_default_start` | `10:00` | 職員が申告しなかった場合の勤務開始 |
| `staff_default_end` | `17:00` | 同、終了 |
| `public_name_style` | `full` | 画面での氏名表示。`family` にすると姓のみ（空白で区切られている場合） |

変更はすぐ反映されます（画面の再読み込みが必要です）。

## 困ったとき

### 「このURLでは開けません」と出る

URLに `?t=…` が付いていないか、トークンが古くなっています。スクリプトエディタで `showViewUrl()` を実行し、出てきたURLで開いてください。

「閲覧トークンが未設定です」と出る場合は `_config` の `view_token` 行が消えています。`setup()` を実行し直すと作り直されます。

### Googleログインを求められる／「アクセス権限が必要です」と出る

このツールは**ログイン不要**の構成です（実行＝自分／アクセス＝全員）。ログインを求められる場合、原因は次のいずれかです。

1. **デプロイのアクセス設定が「全員」になっていない** … 最も多い原因です。「デプロイを管理」→ 鉛筆アイコン →「アクセスできるユーザー」を「全員」へ。`appsscript.json` を直しても既存デプロイには反映されません
2. **`/dev` のURLを配っている** … `/dev` は常にログインと編集権限が必要です。配布には `/exec` を使ってください
3. **Google Workspace の制限** … 組織アカウントの場合、管理コンソールで外部公開が制限されていることがあります（「アプリ」→「Google Workspace」→「Apps Script」）。この場合はコード側では回避できません

確認は**シークレットウィンドウ**で行ってください。

### 「準備ができていません」と出る

`setup()` がまだ実行されていません。スクリプトエディタから実行してください。

### 枠が削除できない

その枠に割り当てが残っています。**連鎖削除は行いません**（事故のもとになるため）。先に割り当てパネルから全員を解除してください。

### 破線の「既定の枠」が表示されない

次のいずれかです。

1. **`_config` に `default_slot_start` / `default_slot_end` / `default_slot_required` の行が無い**（このバージョンより前に `setup()` を実行したシート）。**スクリプトエディタで `setup()` を実行し直してください。** 足りないキーだけが追加され、既にある設定は変わりません
2. その場所には既に枠があります（既定の枠は、枠が1つも無い場所にだけ出ます）
3. 場所の「表示」がオフになっています
4. `default_slot_start` か `default_slot_end` が空になっています（意図的に出さない設定）

### 全員を解除したのに枠が残る

**枠は自動では消えません。** 割り当てをやり直すたびに枠が消えたり生えたりすると、先に決めた予定が失われるためです。空の枠が邪魔なときは、枠をタップ →「この枠を削除」で消してください。

### 同じ場所に枠が2段に並んでしまった

枠と違う時間で人を入れると、その時間の枠が別にできます（仕様です）。1つにまとめたい場合は、枠をタップして時間を直すか、片方の割り当てを解除して枠を削除してください。

### 割り当てた人を候補で見かけない

次のいずれかです。

1. 同じ時間に別の場所へ割り当て済み（ダブルブッキング防止で除外）
2. その日の可用性が枠にまったく重なっていない
3. 枠の一部にしか入れない → 「一部の時間のみ可用」の中にいます

### 応募を取り消したい／人を間違えた

`availability` シートから該当行を削除します。**このとき割り当ては自動では消えません。** 意図せず人が抜けるのを防ぐためで、割り当てを外すのは割り当てパネルから行ってください。

### 同じ人が二重に登録されてしまった

想定内です。人マスタは使い捨て前提で運用します（登録できないことの方が損害が大きいため）。まとめたい場合は `people` シートで、残さない側の `merged_into` に残す側の `id` を書きます。過去の割り当ては自動的に統合先へ読み替えられます。

### 複数人で同時に編集したら

同時編集の競合解決は行っていません（管理者は実質1人ずつという前提です）。ただし応募の受付だけは排他制御しているため、応募が集中しても取りこぼしません。

### ファイル構成

```
main.js           doGet のみ。ルーティングは薄く保つ
api.js            google.script.run から呼ばれる公開関数（検証 → service → 整形）
service_board.js  配置表の組み立て（getBootstrap / getDayBoard）
service_slot.js   場所と枠の書き込み、テンプレート展開、コピー
service_assign.js 割り当て・解除
service_entry.js  可用性の登録受付
service_auth.js   閲覧トークンの検証、エディタ専用関数のガード
repo_sheet.js     シート読み書きの共通処理（バッチ前提）
config.js         シート定義・定数
util.js           日付/時刻変換、区間の重なり判定
setup.js          初回セットアップ、URL表示
test_util.js      util.js の単体テスト
index.html        配置表（場所ごと＋人ごと。style.html / script.html を include）
entry.html        応募フォーム（entry_script.html を include）
common_script.html 両画面で使う処理
```

内部専用関数は末尾にアンダースコアを付けます（`toMinutes_`）。**これが無いと匿名の第三者から `google.script.run` で呼べてしまいます。**

### テスト

スクリプトエディタで **`runUtilTests()`** を実行します。時刻変換と区間判定（`overlaps_` / `covers_`）を検証します。ここのバグは配置表全体を静かに壊すため、`util.js` を触ったら必ず実行してください。

### 覚えておくべき制約

- サーバー呼び出しは画面単位で1回。`getDayBoard(date)` がその日の全データを返し、候補者の絞り込みはクライアント側で計算します
- シートアクセスは `getValues()` / `setValues()` の一括のみ。セル単位のループは書きません
- 書き込みを伴う公開関数はすべて `LockService` で保護します
- 戻り値は `{ ok: true, data }` / `{ ok: false, error }` に統一します
- 列はヘッダー名から解決します（`getColumnMap_`）。列位置のハードコードは禁止です
