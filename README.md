# ボランティアシフト配置ツール

場所×時間帯に、ボランティアと職員を割り当てるためのツールです。
Google Apps Script（GAS）で動き、データはスプレッドシートに入ります。

> ボランティアと職員から「入れる時間帯」を先に集め、場所×時間帯へ、**ボランティア優先で**割り当てる。足りないところを職員が埋める。

**利用者にGoogleアカウントは要りません。** 配布したURL（QRコード）を開くだけで応募できます。

## はじめの設定

初回だけ、次の4ステップを行います。

### 1. コードをスプレッドシートへ入れる

このプロジェクトはスプレッドシートにコンテナバインドしたGASプロジェクトです。

```bash
clasp push
```

### 2. `setup()` を実行する

スクリプトエディタで関数 `setup()` を選んで実行します。初回は認可（アクセスを許可）を求められます。

- 必要なシートとヘッダーが作られます
- `_config` に既定値が入り、閲覧トークンが発行されます
- 日付・時刻の列が「書式なしテキスト」になります（日付型に化けるのを防ぐため）
- `_config` と `_log` は非表示になります

**何度実行しても安全**です。既にある値は上書きしません。

### 3. Webアプリとしてデプロイする

エディタの「デプロイ」→「新しいデプロイ」→ 種類は **ウェブアプリ**。設定は次のとおりにします。

| 項目 | 値 |
|---|---|
| 次のユーザーとして実行 | **自分** |
| アクセスできるユーザー | **全員（匿名ユーザーを含む）** |

この組み合わせでないと、ボランティアがGoogleアカウント無しで応募できません。閲覧者にスプレッドシートの権限は渡りません。

> 2回目以降にコードを直したときは、「新しいデプロイ」ではなく**既存デプロイの「編集」→ バージョンを「新バージョン」**にします。URLが変わらないので、配ったQRコードが無効になりません。

#### ⚠️ アクセス設定は `appsscript.json` では変わりません

`appsscript.json` にも同じ設定（`ANYONE_ANONYMOUS`）が書いてありますが、**これが効くのは新しくデプロイを作るときだけ**です。既にあるデプロイのアクセス設定は、作った時点のもので固定されます。`clasp push` や `clasp deploy` では変わりません。

**ログインを求められる場合は、「デプロイを管理」→ 鉛筆アイコン →「アクセスできるユーザー」を「全員」に変更**してください。URLは変わりません。

確認は**シークレットウィンドウ**（ログアウト状態）で行います。ふだんのウィンドウでは自分がログイン済みのため、切り分けになりません。

### 4. URLを取得する

スクリプトエディタで **`showViewUrl()`** を実行し、実行ログに出る4つのURLを控えます。

```
配置表・閲覧用（見るだけ）: https://script.google.com/.../exec?t=xxxxxxxx
配置表・管理用（割り当てを編集できる）: ...?t=xxxxxxxx&view=admin
応募フォーム（QRコードにするのはこれ）: ...?t=xxxxxxxx&view=entry
代理入力（管理者だけが使う）: ...?t=xxxxxxxx&view=entry&proxy=1
閲覧トークン: xxxxxxxx
```

**必ずこのURLを使ってください。** デプロイ画面に出るURLをそのまま開くと `?t=…` が付いておらず、「このURLでは開けません」と表示されます。

#### ⚠️ `/dev` のURLが出てきたら（ログインを求められる原因）

`showViewUrl()` の出力が `…/dev?t=…` になっている場合、それは**開発者専用のテストURLで、開くとGoogleアカウントのログインを求められます**。ボランティアには配れません。配布できるのは `/exec` で終わるデプロイURLだけです。

この場合は実行ログに警告が出ます。デプロイ画面のウェブアプリURL（`/exec` で終わるもの）をコピーして、スクリプトエディタで一度だけ次を実行してください。

```javascript
setWebAppUrl('https://script.google.com/macros/s/AKfycb…/exec')
```

以降 `showViewUrl()` は正しいURLを出します。

もっと簡単な方法もあります。**デプロイ画面の `/exec` のURLを、そのままブラウザで開くだけ**です（`?t=…` は不要）。画面には「このURLでは開けません」と出ますが、その裏でアプリが自分の公開URLを記録します。そのあと `showViewUrl()` を実行すれば正しい4つのURLが出ます。

> なぜこんな手順が要るのか: Apps Script が返す自分自身のURLは、エディタから実行すると `/dev`、ブラウザからアクセスされたときだけ `/exec` になります。`/dev` と `/exec` はIDそのものが違うため、片方からもう片方を計算することはできません。そこで「一度ブラウザで開いてもらって、そのときのURLを控える」という形にしています。

#### ⚠️ `/a/ドメイン名/` が入ったURLは配れません

Google Workspace のアカウントでスクリプトを持っていると、デプロイ画面には**ドメイン限定の形**のURLが出ます。

```
https://script.google.com/a/example.com/macros/s/AKfycb…/exec   ← 配れない
https://script.google.com/macros/s/AKfycb…/exec                 ← これを配る
```

`/a/example.com/` が入った形は「そのドメインのアカウントでログイン済み」であることが前提のURLです。未ログインで開くとGoogle側のアカウント判定に入り、**`?t=…` がアプリまで届かず「このURLでは開けません」と表示されます**。ログイン済みだと開けてしまうため、シークレットウィンドウで確認しないと気づけません。

デプロイIDは同じなので、**`/a/ドメイン名/` の部分を消すだけ**で匿名アクセスできるURLになります。`showViewUrl()` / `setWebAppUrl()` はこの変換を自動で行うため、通常は意識する必要はありません。

記録したURLは `_config` の `web_app_url` に入ります。デプロイを作り直してURLが変わったときは、`setWebAppUrl()` で入れ替えてください（自動記録は未設定のときだけ働くため、古いURLのまま残ります）。

## 4つのURL

| URL | 誰に渡すか | できること |
|---|---|---|
| `?t=…` | 関係者・見るだけの人 | 配置表の**閲覧のみ**。管理操作のボタンは出ません |
| `?t=…&view=admin` | 管理する人 | 割り当ての作成・編集・解除、場所の管理 |
| `?t=…&view=entry` | **ボランティア全員（QRコード）** | 自分の入れる時間帯を登録する |
| `?t=…&view=entry&proxy=1` | 管理者 | 他の人の代わりに時間帯を登録する（種別も選べる） |

日付を指定して開くこともできます: `?t=…&d=2026-08-10`

### ⚠️ URLの扱いについて

**このツールにログイン機能はありません。** 保護はURLに含まれるトークン1段階だけです。

- URLを知っている人は**誰でも割り当ての作成・編集・解除ができます**
- ボランティアに配るのは応募フォームのURLですが、そこからトークンは見えてしまいます
- **閲覧用と管理用でURLを分けていますが、保護ではありません。** トークンは共通で、閲覧URLに `&view=admin` を足すだけで管理画面が開きます。誤操作を防ぐための画面の分離です
- 誰が操作したかの記名は行いません。`_log` の操作者列には `(管理画面)` と記録されます

これは「単発のボランティアにログインを求めない」ことを優先した上での判断です。URLが広く漏れてしまった場合は、スクリプトエディタで **`regenerateViewToken()`** を実行してください。トークンが作り直され、**以前のURL・QRコードはすべて無効**になります（配り直しが必要です）。

## 使う順番

### ① 場所を登録する

**管理用URL**（`&view=admin`）を開く → 「場所」ボタン。

表示順と場所名を入れて保存します。使わなくなった場所は「表示」のチェックを外します（**行は消えません**。過去の配置表が読めなくなるためです）。

**場所ごとに背景色を選べます。** 場所名の下に並ぶ色（なし／赤／橙／黄／緑／青／紫／灰／茶）をタップすると、配置表の「役割ごと」の行がその色になります。同じ持ち場をまとめて見分けたいときに使ってください。

- 色は**行全体**（場所名の欄とタイムラインの両方）に付きます。横スクロールしても途切れません
- 選べるのは淡い色だけです。文字や割り当ての帯が読めなくなる濃い色は用意していません
- 色を消したいときは「なし」を選びます

### ② 枠の準備は要りません

> **「枠」という考え方は無くなりました。** 以前は「場所×時間の枠を作ってから人を入れる」形でしたが、**1つの場所の同じ時間に入れるのは1人まで**にしたことで枠と割り当てが同じものになり、統合しました。
>
> 配置表の1本の帯が、そのまま「誰がどこにいつ入るか」の1件です。準備しておくものはありません。

同じ時間に複数人を置きたい場合は、**場所を分けて登録してください**（「受付1」「受付2」のように）。

### ③ 応募を集める

応募フォームのURLをQRコードにして配ります。ボランティアは名前・性別・年齢・連絡先・入れる日と時間帯を入れて送信するだけです。

```
入れる日と時間帯
┌─ 8月10日(土) ──────────┐
│ [10:00] 〜 [12:00]    × │
│ [＋ 時間帯を追加]          │
└─────────────────────────┘
[＋ 日付を追加]
```

- **複数の日をまとめて登録できます。** 「＋ 日付を追加」を押すと、**直前の日と同じ時間帯**が入った状態で翌日のブロックが増えます。同じ時間で通う人は日付を足すだけで済みます
- 日によって都合が違う場合は、その日の時間帯だけ直してください
- 時刻は**時と分を直接入力**します（プルダウンではありません）
- 途中で抜ける日は、時間帯を分けて追加できます（例: 10:00〜12:00 と 15:00〜17:00）
- 同じ人が何度送っても、**申告した時間が減ることはありません**（前の申告と合算されます）
- **職員はこの画面から申告しなくてもかまいません。** 職員は登録されていれば毎日候補に出ます（`staff_default_start`〜`staff_default_end` の時間帯）。登録は [職員を一括登録する](#職員を一括登録する)から。特定の日だけ時間帯が違うときにこの画面（`&proxy=1` で種別に「職員」）から申告すると、**その日はその申告が優先されます**
- **深夜までの時間は24時からの続きで入力します。** 「22:00〜26:00」は夜10時から翌朝2時までです（配置表では「22:00–翌02:00」と表示されます）
- **性別と年齢は必須です。** 性別には「回答しない」があるので、答えたくない方もそのまま進めます
- 同じ方（名前と連絡先が一致）が登録し直すと、性別・年齢は**新しい内容で上書き**されます。年齢が変わったときや打ち間違えたときは、もう一度登録してもらってください

紙で集めた分は、代理入力URL（`&proxy=1`）から管理者が入力します。

### ④ 割り当てる

配置表 → **管理用URL**を開きます。入れ方は1通りだけです。

```
【A地点の空いているところをタップ】
   ↓
人を選ぶ      鈴木（申告 09:00–12:00）
   ↓
時間を決める   09:00 〜 12:00   ← 初期値はその人の申告時間。変えられます
   ↓
【この内容で登録】→ A地点に 09:00–12:00 の鈴木さんが入る
```

候補者は**ボランティアが上、職員が下**に並びます。同じ種別の中では、その日の割り当てが少ない人が上に来ます。まずボランティアで埋めて、残りを職員で埋める、という順番で作業できます。

#### すでに入っている帯をタップする

**場所・時間・メモを直すか、その人を外すか**ができます。

**人は替えられません。** 別の人にするときは、いったん「この人を外す」で外してから入れ直してください（誰がいつ外れたかを `_log` に残すためです）。

## 画面の説明

### 配置表

縦が場所、横が時間のタイムラインです。1本の帯が1件の割り当てで、次が出ます。

```
10:00–11:30
田中（女42）
受付の応援
```

- 1行目 … 時間
- 2行目 … 入っている人の名前（「（職）」が職員、管理用URLでは性別・年齢も）
- 3行目 … メモ（入っていれば）

**1つの場所の同じ時間に入れるのは1人までです。** 人数は表示しません。同じ時間に複数人を置きたい場合は、**場所を分けて登録してください**。

帯が細いと文字が `…` で切れます。**帯にマウスを乗せると詳細が出ます**（場所・時刻・氏名・種別・性別年齢・その人の申告時間帯・メモ）。「人ごと」の青い帯でも同じ内容が出て、申告の外に入っている場合は警告が付きます。

> スマホにはマウスホバーがありません。**ホバーでしか見られない情報は置いていません**（すべて帯かパネルで確認できます）。

### 深夜までの時間の見かた

**24時以降は「翌」を付けて表示します。**

```
22:00  23:00  翌00:00 翌01:00 翌02:00
  │      │      │      │      │
  └──── 22:00–翌02:00 鈴木 ────┘
```

- シートには `22:00` 〜 `26:00` の形で入ります（24時間制の続きで数えます）
- 入力するときも `26:00` のように打ちます。表示だけが「翌02:00」になります
- **日付は開始日のまま**です。8月10日の 22:00–26:00 は、8月10日の割り当てとして1本で扱われます
- 入れられるのは `47:59`（翌日の23:59）までです

**翌日の画面にも「前日からの続き」として出ます。**

```
8/11 の配置表

        00:00  02:00  ...
A地点  ╎░░░░░░╎
        前日から 00:00–02:00 鈴木     ← 破線＝前日に登録された分
```

- 破線の帯は**この画面では直せません。** タップすると「8/10 を開く」ボタンが出るので、元の日で直してください
- **`day_start` が早朝を含んでいないと見えません。** 既定の `10:00` のままだと 00:00–02:00 は表示範囲の外なので、深夜帯を扱う場合は `_config` の `day_start` を `00:00` などに変えてください

日付は前後の矢印、カレンダー、「今日」ボタンで切り替えます。

### 管理画面（`&view=admin`）

管理用URLを開くと、上部に操作の列が出ます。**モードの切り替えやログインはありません。** 閲覧用URLでは同じ画面が読み取り専用になり、帯をタップしても何も起きません。

タップした場所で操作が決まります。

| タップした場所 | 開くもの |
|---|---|
| 空いているところ | 人を選んで時間を決める画面（登録すると割り当てができる） |
| すでにある帯 | **割り当てのパネル**（場所・時間・メモの変更と解除） |

### 割り当てのパネル

配置表の帯をタップすると開きます。**できるのは「直す」か「外す」かの2つだけ**です。

```
[ A地点 10:00–11:30 ]

田中さん
女性 / 42歳
申告: 09:00–12:00

場所  [A地点        ▾]
時間  [10:00] 〜 [11:30]
メモ  [                ]

[この人を外す]        [閉じる] [保存]
```

- **人は替えられません。** 別の人にするときは「この人を外す」で外してから入れ直してください
- 時刻を直すと、**その人の重なりや申告外を注意書きで知らせます**（登録自体は止めません）
- **同じ時間に別の場所へ入っている人は候補に出ません**（ダブルブッキング防止）。連続する時間帯（10:00–11:00 と 11:00–12:00）は重ならない扱いなので、同じ人を続けて入れられます
- **同じ場所の同じ時間に2人目は入りません。** 場所を分けて登録してください

### 人ごとの一覧（配置表の下半分）

配置表は上下2段になっています。**上が「役割ごと」、下が「人ごと」**です。同じ日を2つの見方で並べているので、上で埋まり具合を見ながら、下で空いている人を探せます。

```
             10:00      12:00      14:00      16:00
鈴木  空き     ░░░░░░░░░░░░░░░░░░░  ░░░░░░░░░░░░░
高橋          ░░░░░░░░░░[A地点]░░░░░░░░░░░░░░░░░░
伊藤（職員）   ░░░░░░░░░░░░░░░░░░░░░░░░░░░░░
```

- **薄いグレーの帯**が「入れる」と申告された時間、**青い帯**が割り当て済みの時間（場所名入り）です
- **まだ割り当ての無い人が上**に並びます。「あと誰に頼めるか」を探すための順番です
- 上部に、その日の登録人数・まだ割り当ての無い人数・割り当て件数が出ます
- 申告の外に割り当てられている区間は**赤**で表示されます（応募を取り下げた人が割り当てられたままなど）
- 管理用URLでは、**青い帯をタップすると割り当てを解除できます**（確認画面が出ます）
- 管理用URLでは、名前の下に**性別・年齢**が出ます（「女性 / 42歳」）。人を選ぶ画面の候補一覧にも同じ形で出ます

### 性別・年齢の表示について

管理用URLでは、**「役割ごと」と「人ごと」の両方**に性別・年齢が出ます。

| 場所 | 見た目 |
|---|---|
| 役割ごと（帯の中の名前） | `鈴木 花子（女42）` / `伊藤 誠（男38・職）` |
| 人ごと（名前の下） | `女性 / 42歳` |
| 人を選ぶ画面・割り当てのパネル | `女性 / 42歳` |

帯の中だけ短い書き方（`女42`）にしているのは、帯が細いと文字が `…` で切られ、**名前そのものが読めなくなる**ためです。

- **「その他」「回答しない」を選んだ方の性別は出しません**（年齢だけが出ます）。ご本人の控えには選んだとおりに出ます
- 性別・年齢が未入力の方（列を追加する前に登録された方）は、その部分の表示が省かれるだけです

> **性別・年齢は閲覧用URLには出ません。** ただし管理用URLは閲覧用URLに `&view=admin` を足しただけのものなので、**閲覧用URLを配った相手は管理用URLも作れます。** 見られて困る情報は、この画面ではなく `people` シートで管理してください（連絡先と同じ扱いです）。

## 職員を一括登録する

職員が何人もいる場合、1人ずつ応募フォームから入力するのは手間です。**`staff_import` シートに書いて、まとめて登録できます。**

### 手順

1. スプレッドシートのメニュー **「シフト管理 ▸ 一括登録シートを開く（無ければ作る）」** を選びます
   - メニューが出ないときは、スプレッドシートを開き直してください（`setup()` を実行済みであれば `staff_import` シートは既にあります）
2. `staff_import` シートに1人1行、**氏名だけ**書きます（日付は不要です。詳しくは下記）
3. メニュー **「シフト管理 ▸ 職員を一括登録する」** を選びます
4. 結果がダイアログに出ます。各行の `status` 列にも同じ内容が入ります

### 書き方

| 列 | 必須 | 内容 |
|---|---|---|
| `name` | ● | 氏名 |
| `kana` | | ふりがな（並べ替えに使います） |
| `gender` | | `male` / `female` / `other` / `undisclosed`、または `男性` / `女性` / `その他` / `回答しない`。**未記入なら「回答しない」** |
| `age` | | 半角数字。**未記入なら空のまま**（応募フォームと違い、一括登録では任意です） |
| `contact` | | 連絡先。**画面には一切出ません**。同姓同名の別人を分けるのにも使います |
| `start_date` | | 勤務する日（`2026-08-10`）。**ふつうは空のままで構いません**（下記） |
| `end_date` | | 連続して勤務する最終日。未記入なら開始日の1日だけ |
| `start_time` | | 開始時刻（`10:00`）。未記入なら `_config` の `entry_default_start` |
| `end_time` | | 終了時刻（`17:00`）。24時以降は `26:00`（翌2時）。未記入なら `entry_default_end` |
| `note` | | メモ。画面には出ません |
| `status` / `person_id` / `imported_at` | | **自動で入ります。人は書きません**（各列の書き方は、1行目の見出しに付いているメモにも書いてあります） |

### 日付は書かなくて構いません

**登録された職員は、毎日そのまま候補に出ます**（`_config` の `staff_default_start` 〜 `staff_default_end` の時間帯）。氏名だけ並べて取り込めば済みます。

日付を書くのは、**その日だけ時間帯が違うとき**です。

| 書き方 | 結果 |
|---|---|
| 日付を書かない | 毎日、既定の時間帯（`staff_default_*`）で候補に出る |
| 日付と時刻を書く | **その日はその時間帯が優先される**（例: 8月10日だけ 08:00〜12:00 の早番） |

日付を書いた行は `availability` シートに申告として入り、その日は既定より優先されます。取り消したいときは `availability` シートの行を削除してください（既定に戻ります）。

`end_date` や時刻だけを書いて `start_date` を書き忘れた行はエラーにします（どの日か決まらないため）。

### 何度実行しても大丈夫です

- 取り込んだ行には `person_id` が書き戻され、次に実行したときは**同じ人への追記**になります。人は増えません
- 時間帯は既存の申告と重ね合わせるだけなので、同じ行を何度取り込んでも増えません（`10:00–12:00` と `11:00–13:00` は `10:00–13:00` の1本にまとまります）
- **書き間違えた行があっても、他の行は取り込まれます。** その行の `status` に理由が出るので、直してもう一度実行してください

### 気をつけること

- **`person_id` 列を消すと、次の実行で別の人として登録されます**（重複の原因になります）
- 日付を書き換えて再実行すると、新しい日が**足されます**。前の日の申告は消えません。消したいときは `availability` シートの行を直接削除してください
- 既に登録済みの人が見つかった場合、シートに書いた列だけを上書きします。**種別（`type`）は書き換えません。** ボランティアとして登録済みの人がこのシートにあると、`status` に「種別は volunteer のままです」と出ます

## 困ったとき

### 「このURLでは開けません」と出る

URLに `?t=…` が付いていないか、トークンが古くなっています。スクリプトエディタで `showViewUrl()` を実行し、出てきたURLで開いてください。

**ログイン済みだと開けるのに、シークレットウィンドウでだけこう出る場合**は、URLに `/a/ドメイン名/` が入っています。その部分を消してください（[詳細](#-aドメイン名-が入ったurlは配れません)）。

「閲覧トークンが未設定です」と出る場合は `_config` の `view_token` 行が消えています。`setup()` を実行し直すと作り直されます。

### Googleログインを求められる／「アクセス権限が必要です」と出る

このツールは**ログイン不要**の構成です（実行＝自分／アクセス＝全員）。ログインを求められる場合、原因は次のいずれかです。

1. **デプロイのアクセス設定が「全員」になっていない** … 最も多い原因です。「デプロイを管理」→ 鉛筆アイコン →「アクセスできるユーザー」を「全員」へ。`appsscript.json` を直しても既存デプロイには反映されません
2. **`/dev` のURLを配っている** … `/dev` は常にログインと編集権限が必要です。配布には `/exec` を使ってください。`showViewUrl()` が `/dev` のURLを出す場合は、デプロイ画面のURLを `setWebAppUrl('…/exec')` で登録してください（[手順](#-dev-のurlが出てきたらログインを求められる原因)）
3. **Google Workspace の制限** … 組織アカウントの場合、管理コンソールで外部公開が制限されていることがあります（「アプリ」→「Google Workspace」→「Apps Script」）。この場合はコード側では回避できません

確認は**シークレットウィンドウ**で行ってください。

### 「準備ができていません」と出る

`setup()` がまだ実行されていません。スクリプトエディタから実行してください。

### 応募フォームで「性別を選んでください」から先に進めない／登録がエラーになる

**`people` シートに `gender` / `age` 列がありません**（このバージョンより前に `setup()` を実行したシート）。**スクリプトエディタで `setup()` を実行し直してください。** 足りない列だけが右端に追加され、既存のデータは変わりません。

なお、列を追加する前に登録された方は性別・年齢が空欄のままです。画面ではその部分の表示が省かれるだけで、割り当てには影響しません。埋めたい場合は `people` シートに直接書くか、本人にもう一度登録してもらってください。

### 「枠」が無くなった／既定の枠の破線が出ない

**枠という考え方ごと廃止しました。** 1つの場所の同じ時間に入れるのは1人までにしたことで、枠と割り当てが同じものになったためです。

配置表の1本の帯が、そのまま「誰がどこにいつ入るか」の1件です。作るのは1通りだけで、**空いているところをタップして人と時間を選ぶ**だけです。

`_config` に残っている `default_slot_start` / `default_slot_end` / `default_slot_required` の行は、消して構いません（残っていても動作に影響しません）。

### バージョンアップ後、割り当てが消えた／画面が真っ白になる

**`migrateSlots()` を実行していません。** スクリプトエディタから1回だけ実行してください。

旧 `slots` シートと旧 `assignments` シートを読んで、新しい形の `assignments` に作り直します。**何度実行しても安全**です（移行済みなら何もしません）。

- 旧シートは `slots_old_20260805_120000` のように名前を変えて残ります。**消しません**
- **誰も入っていなかった枠は移行されません。** 新しい形は「人が入っていること」が前提のためです。件数を実行ログに出すので、必要なら旧シートを見て画面から入れ直してください

### 同じ場所に帯が2段に並んでしまった

通常は起きません（同じ場所の同じ時間には1人までのため）。並んでいる場合は、**スプレッドシートを直接編集して重なりが作られています**。画面はあえて隠さずに段で表示します。どちらかの帯をタップして時間を直すか、解除してください。

### 職員が候補に出てこない

**職員は登録されていれば毎日候補に出ます。** 出てこない場合は次を確認してください。

1. **`people` シートの `type` が `staff` になっていますか**（小文字の半角。`職員` や `Staff` では判定されません）
2. **`is_recurring` が `TRUE` になっていますか。** `FALSE` の職員は候補に出ません（退職者を外すための設定です）
3. `merged_into` に値が入っていませんか（名寄せ済みの行は、統合先の名前で出ます）
4. **その日に申告がありませんか。** 申告がある日は、既定の時間帯ではなく**申告した時間帯**で出ます

登録は [職員を一括登録する](#職員を一括登録する)（`staff_import` シート）が簡単です。1人だけなら `people` シートに直接足しても構いません。

出てくる時間帯は `_config` の `staff_default_start` 〜 `staff_default_end` です。

### 割り当てた人を候補で見かけない

次のいずれかです。

1. **その日の時間帯を申告していません。** 申告のある人だけが候補に出ます
2. 名寄せ元（`merged_into` に値がある行）です。統合先の名前で出ています

なお、人を選ぶ画面では**その日に申告のある人を全員出します**。時間がまだ決まっていないためです。同じ時間に別の場所へ入っている場合は、時間を決める画面で注意書きが出て、登録時にサーバー側が弾きます。

### 応募を取り消したい／人を間違えた

`availability` シートから該当行を削除します。**このとき割り当ては自動では消えません。** 意図せず人が抜けるのを防ぐためで、割り当てを外すのは割り当てパネルから行ってください。

### 同じ人が二重に登録されてしまった

想定内です。人マスタは使い捨て前提で運用します（登録できないことの方が損害が大きいため）。まとめたい場合は `people` シートで、残さない側の `merged_into` に残す側の `id` を書きます。過去の割り当ては自動的に統合先へ読み替えられます。

### 複数人で同時に編集したら

同時編集の競合解決は行っていません（管理者は実質1人ずつという前提です）。ただし応募の受付だけは排他制御しているため、応募が集中しても取りこぼしません。

### 覚えておくべき制約

- サーバー呼び出しは画面単位で1回。`getDayBoard(date)` がその日の全データを返し、候補者の絞り込みはクライアント側で計算します
- シートアクセスは `getValues()` / `setValues()` の一括のみ。セル単位のループは書きません
- 書き込みを伴う公開関数はすべて `LockService` で保護します
- 戻り値は `{ ok: true, data }` / `{ ok: false, error }` に統一します
- 列はヘッダー名から解決します（`getColumnMap_`）。列位置のハードコードは禁止です
