# ボランティアシフト配置ツール

Google Apps Script（GAS）で構築する、場所×時間帯のシフト配置管理Webアプリ。

## このプロジェクトを触る前に

1. **`gas.md`（GAS Webアプリ開発方針）を必ず読むこと。** 本プロジェクトはその方針に完全準拠する。矛盾がある場合は `gas.md` が優先。
2. `docs/requirements.md` … 何を作るか（業務要件・スコープ）
3. `docs/design.md` … どう作るか（シート定義・API・ロジック）
4. `docs/roadmap.md` … どの順で作るか（フェーズと受け入れ条件）

実装に入る前に上記3つを通読すること。特に `docs/design.md` の「6. 重要ロジック」は、本ツールの中核であり、ここを間違えると成立しない。

## 一行で言うと

> ボランティアと職員から「入れる時間帯」を先に集め、場所×時間帯の枠へ、**ボランティア優先で**割り当てる。足りない枠を職員が埋める。

## 絶対に守る設計判断

以下は検討済みの決定事項。実装中に「こうした方が良いのでは」と思っても、**勝手に変更せず必ず確認を取ること。**

| 決定 | 理由 |
|---|---|
| 利用者にGoogleアカウントを要求しない | 単発ボランティアが大半。ログインは参加障壁になる |
| デプロイは「実行=自分／アクセス=全員（匿名可）」 | 上記を満たす唯一の構成 |
| 認証は行わない。閲覧トークンのみ（Google認証も合言葉も使わない） | 同上。管理操作は「操作者の記名」で追跡する。**URL（QRコード）を配った相手は全員が枠を編集できる**前提で運用する |
| 連絡先（`people.contact`）は画面に一切返さない | 管理者だけを識別する手段が無いため。必要なときは people シートを直接見る |
| 同時編集の競合解決はしない | 管理者は実質1人ずつ。ただし**応募受付だけはLock必須** |
| 自動割り当て（最適化）は作らない | 暗黙の事情で人が直すため、投資対効果が合わない |
| **1つの場所の同じ時間に入るのは1人まで** | 複数人が要る場所は場所そのものを分けて登録する運用にした |
| **枠（slots）は持たない。割り当て1行が場所・時間・人を丸ごと持つ** | 上の決定により枠と割り当てが1対1になり、分ける意味が無くなった |
| **不足の可視化（充足判定・未充足枠一覧）は作らない** | 枠が無いため「必要だがまだ誰もいない」を表せない。**やるなら場所ごとの必要時間帯を持つテーブルから設計し直すこと** |
| 時刻は24時間制の延長。24〜47時は翌日 | 日をまたぐ割り当てを1行で持つため。`date` は開始日のまま動かさない |
| メール・通知機能は作らない | スコープ外。連絡は既存の手段で行う |
| 日付・時刻は文字列で保持する | `YYYY-MM-DD` / `HH:mm`。詳細は design.md 5.1 |
| 人マスタは「使い捨て前提」で運用する | 単発参加者の重複・表記ゆれは許容し、名寄せは手動 |
| **職員は申告が無くても毎日候補に出す**（`staff_default_*` を仮想的に補う） | 職員は勤務が前提で、毎日申告させる意味が薄い。**補った行を `availability` シートに書かないこと**（本人の申告と区別が付かなくなる）。申告がある日はそちらが優先 |
| **職員の一括登録シート（`staff_import`）では日付は任意** | 上の決定により、ふつうは氏名だけでよい。日付を書く行は「その日だけ別の時間帯」を表す |

## 技術構成

- **形態**: スプレッドシートにコンテナバインドしたGASプロジェクト
- **UI**: HtmlService（素のJS＋テンプレートリテラル。フレームワーク・ビルド工程なし）
- **DB**: バインド先スプレッドシート（`SpreadsheetApp.getActiveSpreadsheet()`。IDのハードコード禁止）
- **バージョン管理**: clasp + Git（`appsscript.json` もコミットする）

## ファイル構成

```
main.js          … doGet のみ。ルーティングは薄く保つ
api.js           … google.script.run から呼ばれる公開関数。検証→service呼び出し→整形のみ
service_board.js … 配置表の組み立て
service_place.js … 場所の登録・編集
service_assign.js… 割り当ての作成・編集・解除
service_entry.js … 可用性の登録受付（応募フォーム）
service_staff_import.js … 職員の一括登録（staff_import シートの取り込み）
service_auth.js  … 閲覧トークンの検証とエディタ専用関数のガード
repo_sheet.js    … シート読み書きの共通処理（バッチ前提）
migrate.js       … 枠（slots）廃止にともなう1回きりのデータ移行
menu.js          … スプレッドシートのメニュー（onOpen）。組み立て以外を書かない
config.js        … シート定義・定数
util.js          … 日付/時刻変換、区間の重なり判定など
index.html       … 配置表（上=場所ごと／下=人ごと。style.html / script.html に分割）
```

内部専用関数は末尾アンダースコア（`toMinutes_`）を付ける。

## 開発ルール

- **サーバー呼び出しは画面単位で1回。** 特に `getDayBoard(date)` は、その日の描画に必要な全データ（枠・割り当て・人・可用性）をまとめて返す。候補者の絞り込みはクライアント側で計算する（サーバー往復を発生させない）。ただし保存時はサーバー側で必ず再検証する。
- **シートアクセスは必ず `getValues()` / `setValues()` の一括。** セル単位ループは禁止。
- **書き込みを伴う公開関数はすべて `LockService` で保護する。**
- 戻り値は `{ ok: true, data }` / `{ ok: false, error: 'ユーザー向けメッセージ' }` に統一。
- 列参照はヘッダー名から解決する（`getColumnMap_`）。列位置のハードコード禁止。
- スマホでの利用が前提。レスポンシブ対応は必須。

## 作業の進め方

- フェーズ単位で実装し、各フェーズの受け入れ条件（`docs/roadmap.md`）を満たしたら止めて確認を取る。先のフェーズを勝手に始めない。
- 仕様が曖昧な箇所に出会ったら、推測で埋めずに質問すること。特に運用フローに関わる部分は現場の事情に依存する。
- `util.js` の時刻変換と区間重なり判定は、実装したら必ず単体で動作確認する。ここのバグは配置表全体を静かに壊す。
