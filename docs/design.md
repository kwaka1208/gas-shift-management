# 設計

`gas.md` の方針に準拠する。以下はその上でのプロジェクト固有の設計。

## 1. 全体構成

```
[ボランティア] ──URL/QR──▶ 可用性登録フォーム ─┐
                                              │
[管理者] ──管理URL──────▶ 配置表／割り当て画面 ─┼─▶ google.script.run
                                              │
[閲覧者] ──URL──────────▶ 配置表（読み取り）  ─┘         │
                                                        ▼
                                              GAS（api.js → service_*.js）
                                                        │
                                                        ▼
                                              スプレッドシート（1シート＝1テーブル）
```

デプロイ設定は **実行ユーザー: 自分 / アクセス: 全員（匿名ユーザーを含む）**。
利用者はGoogleアカウント不要。その代わりシートの権限は一切渡らない。

## 2. 認証設計

**認証は行わない。** 保護はURLに含まれる推測困難なトークン（`?t=xxxxx`）の1段階だけ。

| 種別 | 方式 | 用途 |
|---|---|---|
| 閲覧・管理を通じて | URLに推測困難なトークン（`?t=xxxxx`） | すべての画面・すべてのAPI |

- 閲覧トークンは `_config` シートに保持する。
- **すべての公開関数で、読み書きを問わずサーバー側でトークンを検証する。** クライアント側の画面制御だけに頼らない。
- 漏えい時は `regenerateViewToken()` で作り直す。以前のURL・QRコードは無効になるため配り直しが必要。

### この設計で守れるもの・守れないもの

| | |
|---|---|
| 守れる | URLを知らない第三者からのアクセス |
| **守れない** | **URLを知っている人による編集・削除** |

QRコードを配った相手（＝ボランティア全員とその転送先）は、全員が割り当てを作成・削除できる。これは受け入れた上での判断である。

### 画面の分離（認証ではない）

閲覧用と管理用でURLを分ける。

| URL | 画面 |
|---|---|
| `?t=<token>&view=board` | 配置表（見るだけ。管理操作のボタンを出さない） |
| `?t=<token>&view=admin` | 配置表（割り当ての作成・編集・解除ができる） |

**同じ画面（`index.html`）で、`boot.admin` の真偽だけが違う。** モードの切り替えUIは持たない。

**これは保護ではない。** トークンは共通なので、閲覧URLを知っていれば `view=admin` を足すだけで管理画面を開ける。サーバー側も閲覧トークンしか見ない。**誤操作を防ぐための画面の分離**であり、それ以上の意味を持たせないこと。

### 誰が変更したかの記録

**記名は行わない。** 管理URLを開けば誰でも操作できるため、操作者を特定する手段が無い。`_log` の操作者列には固定値（`LOG_OPERATOR`）を入れ、記名していないことが分かるようにする。

> 以前は管理モードに入る際に操作者名を選ばせていたが、モード切り替えの廃止に伴ってやめた。誰が変更したかを追う必要が出たら、URLごとにトークンを分ける設計から検討し直すこと。

### 連絡先の非公開

上記のとおり管理者だけを識別する手段が無いため、**`people.contact` と `people.note` はどの画面にも返さない。** サーバー側（`toPublicPerson_`）で落とす。連絡先が必要な場面では、管理者がスプレッドシートの `people` シートを直接参照する。

### 性別・年齢の扱い（目隠しであって秘匿ではない）

`people.gender` と `people.age` は、`getDayBoard(token, date, admin)` の `admin` が true のときだけ返す。

**これは保護ではない。** 上の「管理URL」と同じで、閲覧URLを知っていれば `admin` に true を渡せる。効果は「閲覧用URLを配った相手の目に触れにくくする」ことに留まる。

したがって判断の基準はこうなる。

- **配布先の全員に見られても構わない情報だけを載せる。** 性別・年齢はこの条件を満たすという判断で載せている
- **本当に見せてはいけない情報は、`contact` と同じく `admin` に関係なく落とす。** `admin` フラグで守ろうとしないこと

## 3. シート定義

1シート＝1テーブル。1行目がヘッダー（列ID）、2行目以降がデータ。
全テーブルに `id`（`Utilities.getUuid()`）、`created_at`、`updated_at` を持たせる。**行番号をIDとして使わない。**

### `places`

| 列 | 型 | 説明 |
|---|---|---|
| id | string | UUID |
| name | string | 役割名 |
| sort_order | number | 配置表での表示順 |
| active | boolean | 廃止した役割は false（行は消さない） |
| color | string | 配置表で行の背景に敷く色。空欄は色なし |

`color` に入れるのは**色そのものではなくキー**（`red` / `blue` …。`PLACE_COLORS`）。実際の色は `style.html` の `--tint-*` が決める。濃さを直したいときに保存済みのデータを触らずに済み、文字が読めなくなる色を選べないようにできるため。**知らない値はサーバーが空として返す**ので、シートを手で書き換えても画面は壊れない。

色は役割名の列とタイムラインの**両方**に敷く。役割名の列は横スクロールしても左に貼り付くので、片方だけ塗ると色が途切れて見える。

### `people`

**使い捨て前提のテーブル。** 単発参加者の重複・表記ゆれは許容する。継続参加者のみ管理者が手動で名寄せする。

| 列 | 型 | 説明 |
|---|---|---|
| id | string | UUID |
| name | string | 表示名 |
| kana | string | 並べ替え用（任意） |
| gender | string | `male` / `female` / `other` / `undisclosed`。応募フォームでは必須 |
| age | number | 0〜120。応募フォームでは必須 |
| type | string | `volunteer` / `staff` |
| contact | string | 連絡先。**公開ビューには絶対に出さない** |
| is_recurring | boolean | 継続参加者フラグ。true の人だけ次回以降の候補に自動で出す |
| merged_into | string | 名寄せ時に統合先の person_id を記録（行は消さない） |
| note | string | |

`gender` は `type` と揃えて英語コードで保存し、日本語への変換は画面側で行う（サーバー: `config.js` の `GENDER` / `GENDER_VALUES`、クライアント: `common_script.html` の `GENDER_OPTIONS`。**値を足すときは両方直す**）。

`age` の 0〜120 という上限は、打ち間違い（西暦を入れた、桁を余分に打った）を弾くためのもので、参加できる年齢の制限ではない。運用上の可否は人が判断する。

同一人物と判定された再登録（氏名と連絡先が完全一致）では、`gender` / `age` を**今回の申告で上書きする。** 年をまたげば年齢は変わるうえ、本人が打ち間違いを直す手段が応募フォームしか無いため。`kana` も同じ理由で上書きするが、**入力があるときだけ**（空で送られても既存のふりがなは消さない）。氏名・連絡先・種別は照合の鍵や運用上の設定なので触らない。

### `availability`

| 列 | 型 | 説明 |
|---|---|---|
| id | string | UUID |
| person_id | string | |
| date | string | `YYYY-MM-DD` |
| start_time | string | `HH:mm` |
| end_time | string | `HH:mm` |

1人が同じ日に複数行を持てる。日をまたぐ申告は `22:00`〜`26:00` のように24時超で1行にする（5.1）。

**職員には既定の勤務時間帯（`staff_default_*`）を仮想的に補う**（`appendStaffDefaultAvailability_`）。対象は `type=staff` かつ `is_recurring` かつ名寄せされていない人で、**その日に本人の申告がある職員には補わない**（申告が優先）。前日から繰り越した行（`carried_from`）は「その日の申告」と数えない。前夜の勤務の続きであって、その日の勤務を申告したわけではないため。

> この補完は一度廃止して復活させた経緯がある。**仮想の行を `availability` シートに書かないこと。** 書くと本人の申告と見分けが付かず、既定を変えても書いた行は変わらず、日付を開くたびに行が増える。補った区間には `virtual: true` を付けて返し、画面は「申告」と表示しない。

候補から外したい職員（退職者など）は `is_recurring` を `FALSE` にする。

### `assignments`

**1行が「この日・この役割・この時間に、この人が入る」を丸ごと表す。**

| 列 | 型 | 説明 |
|---|---|---|
| id | string | UUID |
| date | string | `YYYY-MM-DD` |
| place_id | string | |
| start_time | string | `HH:mm`（10分単位。24時超は翌日。5.1） |
| end_time | string | `HH:mm` |
| person_id | string | |
| note | string | 任意メモ |
| assigned_by | string | 操作者名。記名は行わないため固定値が入る（2 参照） |

> **かつては `slots`（枠）と `assignments`（割り当て）の2枚だった。**
> 1つの枠に入るのは1人まで（6.6）という方針にした結果、両者は常に1対1になり、
> 分けて持つ意味が無くなったため統合した。`slot_templates` も枠が前提だったので廃止。
>
> **この統合で失ったもの: 「必要だがまだ誰もいない」を表せない。**
> 枠だけが存在する状態が作れないため、不足を機械的に出せない（旧 Phase 4 の充足判定・
> 未充足枠一覧は取り下げた）。**必要になったら、役割ごとの必要時間帯を持つテーブルを
> 足すところから設計し直すこと。** `assignments` に空行を作って表そうとしてはいけない。
>
> 既存データの移行は `migrateSlots()`（`migrate.gs`）。旧シートは
> `slots_old_YYYYMMDD_HHmmss` のように名前を変えて残す。**割り当ての無い枠は移行されない。**

### `staff_import`

**職員の一括登録用の入力シート。人が手で書き込む唯一のシート。**

ここだけは業務データではなく「取り込みの指示書」であり、取り込みが終われば消してよい。実データは `people` と `availability` に入る。

| 列 | 型 | 説明 |
|---|---|---|
| name | string | 氏名（必須） |
| kana | string | 任意 |
| gender | string | 任意。コードのほか `男性` / `女性` 等の日本語も受ける（`GENDER_ALIASES`）。未記入は `undisclosed` |
| age | string | 任意。**数値列にしない**（`42歳` のような書き方を空欄と区別して弾くため） |
| contact | string | 任意。同姓同名の別人を分ける鍵 |
| start_date | string | 勤務する日（**任意**）。`YYYY-MM-DD` |
| end_date | string | 連続勤務の最終日（任意）。未記入なら開始日の1日だけ |
| start_time / end_time | string | 任意。未記入なら `entry_default_start` / `entry_default_end` |
| note | string | 任意 |
| status / person_id / imported_at | string | **取り込み結果の書き戻し用。人は書かない** |

**日付は書かなくてよい。** 職員は既定の勤務時間帯で毎日候補に出るため（3章 `availability`）、ふつうは氏名だけ並べれば済む。日付を書いた行はその日の申告として `availability` に入り、**既定より優先される**（「この日だけ早番」を表せる）。

ただし `end_date` や時刻だけがあって `start_date` が無い行はエラーにする。**開始日の書き忘れを「毎日出るからいい」と黙って流すと、意図した勤務が消える。**

**再実行の安全性は `person_id` の書き戻しで担保する。** 取り込んだ行にはその人の id が書かれ、次の実行では「同じ人への追記」になる。可用性は既存との和集合を取るだけ（`addAvailabilityBatch_`）なので、同じ行を何度取り込んでも増えない。

同一実行の中では、氏名＋連絡先が同じ行を同一人物とみなす。**1人の複数時間帯は行を分けて書く。** 人マスタの照合規則は応募フォームと同じ（連絡先が空の行は既存と突き合わせない）。

既存の人が見つかったときは、シートに書かれた列だけを上書きする。**`type` と `is_recurring` は書き換えない**（ボランティア登録済みの人を一括登録の都合で職員に変えない。`status` に注記するだけ）。

### `_config`

`key` / `value` の2列。運用者が触ってよいシート。

| key | 例 | 説明 |
|---|---|---|
| view_token | `a8f3...` | 閲覧URLのトークン |
| day_start | `10:00` | **一日の全体の時間範囲**の開始。配置表タイムラインの左端 |
| day_end | `17:00` | 同、終了。深夜までの日は `26:00` のように24時超で書く（5.1） |
| slot_unit_minutes | `10` | 時刻選択の刻み |
| entry_default_start | `10:00` | **登録画面（応募フォーム）に最初から入っている時間帯**の開始 |
| entry_default_end | `17:00` | 同、終了 |
| staff_default_start | `10:00` | **職員の既定の勤務時間帯**の開始。申告の無い職員はこの時間帯で毎日候補に出る（3章 `availability`） |
| staff_default_end | `17:00` | 同、終了 |
| public_name_style | `full` / `family` | 公開ビューでの氏名表示粒度 |

`day_*` と `entry_*` を分けているのは、**一日の全体範囲をそのまま申告の初期値にすると広すぎる**ため。全体範囲は配置表の横軸を決めるもので、申告してほしい時間とは別物。

`entry_*` と `staff_*` を分けているのは、**応募フォームの初期値と職員の勤務時間帯が同じとは限らない**ため（職員だけ 9:00〜18:00 ということがある）。

> **`staff_default_*` は一度廃止して復活させた。** 職員も申告する運用に変えた際に補完ごと廃止したが、職員を毎日候補に出す運用に戻したため。以前この設定を使っていたシートには古い値が残っており、**復活と同時にその値が効く**（`seedConfigDefaults_` は既存値を上書きしない）。

> **廃止したキー**（`CONFIG_RETIRED_KEYS`）。既存シートには行が残るが動作に影響しない。`setup()` が残っていることを知らせる。
>
> - `default_slot_start` / `default_slot_end` / `default_slot_required` … 「既定の枠」ごと廃止（4.2.2）

### `_log`

`timestamp` / `operator` / `action` / `target_id` / `detail`。運用者がシートで直接見られることが重要。

## 4. 画面

すべて `doGet(e)` からパラメータで振り分ける。ルーティングは薄く保つ。

| URL | 画面 | 認証 |
|---|---|---|
| `?t=<token>&view=board&d=YYYY-MM-DD` | 配置表・閲覧用（既定。日付省略時は当日） | 閲覧トークン |
| `?t=<token>&view=admin&d=YYYY-MM-DD` | 配置表・管理用 | 閲覧トークン |
| `?t=<token>&view=entry` | 可用性登録フォーム | 閲覧トークン |
| `?t=<token>&view=print&d=YYYY-MM-DD` | 印刷用配置表 | 閲覧トークン |

board と admin は同じテンプレート（`index.html`）を使い、`boot.admin` で出し分ける（2 の「画面の分離」）。

### 4.1 配置表（board）

- 縦軸=役割（`sort_order` 順）、横軸=時間（`day_start`〜`day_end`）のタイムライン
- **10分刻みは目盛りとして描くだけ。** 割り当ての帯は開始・終了時刻から幅を計算して配置する。10分刻みのセルを敷き詰める実装にしないこと（列数が爆発し、DOMもデータも破綻する）
- 各帯に「時間 / 入っている人の氏名 / メモ」を表示。**人数は出さない**（同じ役割の同じ時間には1人までなので数える意味がない。6.6）
- 氏名には管理URLでのみ性別・年齢と職員の印を括弧で添える（「鈴木 花子（女42）」「伊藤 誠（男38・職）」）。**ブロックは1行で `…` に切られるため、括弧の中身は短縮形にする**（4.1.2）
- 色分け:
  - 赤: ボランティアだけでは不足
  - 黄: 職員込みで充足（＝職員の穴埋めが入っている）
  - 緑: ボランティアだけで充足
  - 警告アイコン: 職員必須なのに未配置／可用性のない割り当てがある
- 日付切り替え（前日・翌日・カレンダー選択）
- 管理URLでは各ブロックがタップ可能になり、割り当てパネルが開く
- 画面の下半分に「人ごと」の一覧を並べる（4.1.1）
- **モードの切り替えは持たない。** 空いているところをタップすれば人を選ぶ画面（4.2.1）、帯をタップすれば割り当てのパネル（4.2）

### 4.2 割り当てのパネル（管理URL）

配置表の帯をタップすると開くモーダル。**できるのは「直す」か「外す」かの2つだけ。**

```
[ A地点 10:00–11:30 ]

田中さん
女性 / 42歳
申告: 09:00–12:00

役割  [A地点        ▾]
時間  [10:00] 〜 [11:30]
メモ  [                ]

[この人を外す]        [閉じる] [保存]
```

> **かつてここは「枠のパネル」で、下半分に候補者の一覧が並んでいた。**
> 枠と割り当てが1対1になったので、**「人を足す」という操作そのものが無くなった。**

- **人は変えられない。** 替えるときは外してから入れ直す。ここで一緒にできるようにすると、`_log` 上で誰がいつ外れたのかが追えなくなる
- 時刻を触るたびに、その人の重なり・申告外を注意書きで知らせる。**ただし登録は止めない**（判定はサーバー側が本体）
- **楽観的更新をしない。** 同じ役割・同じ時間の重なりはサーバーでしか正しく判定できず、先に画面へ置くと巻き戻しが増える

### 4.2.1 割り当てのしかたは1通りだけ

**役割の空いているところをタップし、人と時間を選ぶ。** これが唯一の経路。

```
[ 役割の空きをタップ ]
      ↓
人を選ぶ      鈴木（申告 09:00–12:00）
      ↓
時間を決める   09:00 〜 12:00   ← 初期値はその人の申告時間
      ↓
[この内容で登録] → 割り当てが1件できる
```

順番は**人 → 時間**。先に人を選べば、その人が申告した時間帯をそのまま初期値にできる（「来られる時間をそのまま入れる」運用に合う）。

人を選ぶ画面には、**その日に申告のある人を全員出す**。時間が決まっていないのでダブルブッキングの除外ができないため、重なりは時間を決める画面で知らせ、最終的にサーバー側が弾く。

必要人数は入力させない（6.6）。

> **かつては「先に枠を作る」経路（週テンプレート展開・日/週コピー・既定の枠）があった。すべて廃止した。**
> 枠が無くなり、「まだ誰も入っていない状態」を作れなくなったため、先に作る対象そのものが無い。

### 4.1.1 人ごとの一覧（配置表の下半分）

配置表は**同じ日を2つの見方で縦に並べる**。切り替えではなく上下に並べるのは、片方を見ながらもう片方を直す作業だから。

```
役割ごと   ← どこが埋まっているか
─────────
人ごと     ← 誰がまだ空いているか
```

下半分は縦が人、横が時間。

```
             10:00      12:00      14:00      16:00
鈴木  空き     ░░░░░░░░░░░░░░░░░░░  ░░░░░░░░░░░░░
高橋          ░░░░░░░░░░[A地点]░░░░░░░░░░░░░░░░░░
伊藤(職)      ░░░░░░░░░░░░░░░░░░░░░░░░░░░░░
             ░ 入れる時間   ■ 割り当て済み
```

- **可用の帯の上に、割り当ての帯を重ねて描く。** 申告のうちどこが埋まってどこが空いているかを、目で追わずに分かるようにするため
- **時間の合計（「2時間 / 5時間」）は出さない。** 帯を見れば埋まり具合は分かるうえ、分母（申告の合計）は表示範囲で切らずに数えるため、帯の長さと数字が食い違って見える。まだ誰にも割り当てていない人にだけ「空き」と出す
- 並び順は**当日の割り当てが少ない順**、同数ならボランティア先、次に `kana`。「あと誰に頼めるか」を探す画面なので、余裕のある人が上に来る
- 出すのは**その日に関わりのある人だけ**（申告した人、または割り当てのある人）。継続参加者でも申告が無ければ出さない。空行が並ぶと目的が埋もれる
- 申告の外に割り当てられている区間は赤で描き、氏名の下に「申告外 N件」を出す。**これは判定結果ではなくその場の見た目**で、クライアント側で計算している（6.4 / 6.5 は取り下げ）
- `people` に無い `person_id` の割り当ても「(不明な人)」として行を作る。**割り当てを画面から消さない**
- 管理URLでは氏名の下に性別・年齢を添える（「女性 / 42歳」）。人を選ぶ画面の候補リストにも同じ形で出す（4.1.2）

- 管理URLでは、**割り当ての帯をタップすると解除できる**。帯は小さく指が触れただけで人が消えると気付けないため、**ここだけは確認を挟む**（割り当てパネルの解除ボタンは即時）

データは `getDayBoard` 1回で足りるため、**この一覧のために新しいAPIは作らない。**

実装上の注意:

- **イベント登録は `#board` / `#people` の中だけを探すこと。** 人ごとの一覧も同じ骨組み（`.board__lanes`）を使っているため、`document` 全体から拾うと人の行をタップしたときに人を入れる画面が開く
- 割り当て・解除のあとは**両方を描き直す**（`refreshAssignView`）。片方だけだと数字が食い違う

### 4.1.2 性別・年齢の出しかた

管理URLでのみ、次の3か所に出す。表記は `script.html` の `personMeta`（一覧向け）と `personMetaShort`（帯向け）に集約する。

| 役割 | 表記 | 例 |
|---|---|---|
| 役割ごと（割り当ての帯） | 短縮形。氏名のうしろに括弧で添える | `鈴木 花子（女42）` / `伊藤 誠（男38・職）` |
| 人ごと（氏名欄） | 通常形。氏名の下に小さく | `女性 / 42歳` |
| 人を選ぶ画面の候補リスト（4.2.1） | 通常形。氏名の下に小さく | `女性 / 42歳` |
| 割り当てのパネル（4.2） | 通常形。氏名の下に小さく | `女性 / 42歳` |

配置表の帯だけ短縮形にするのは、帯が1行で、はみ出すと `…` で切られるため。ここが長くなると**氏名そのものが読めなくなる。**

切れて読めなかった分は、帯の `title`（ホバー）で補う（`assignmentTooltip`）。役割・時刻・氏名・種別・性別年齢・申告時間帯・メモを1項目1行で並べる。**スマホにはホバーが無いため、ここにしか無い情報を置いてはいけない。**

**「その他」「回答しない」を選んだ人の性別は出さない**（`GENDER_OPTIONS` の `short` を空にして表す）。配置表に並べても割り当ての判断材料にならないうえ、答えなかったこと自体が一覧で目立ってしまうため。ただし応募者本人の控えには、選んだとおりに出す。

したがって「性別だけ」「年齢だけ」「どちらも無し」のすべてが起こりうる。**あるものだけを出し、無い項目の区切り文字や括弧を残さないこと。** 列を追加する前に登録された人は、どちらも未入力になる。

### 4.3 可用性登録フォーム（entry）

ボランティアがQRコードから開く。**この画面のわかりやすさが参加率に直結する。**

- 入力項目: 名前 / ふりがな / **性別** / **年齢** / メールアドレス / **入れる日と時間帯（複数日）**
- ふりがなは**任意**。`people.kana`（並べ替え・検索用）に入る。漢字を変換して確定すると、IMEの変換イベントから読みを拾って自動で入る（`entry_script.html` の `setupKanaAutoFill`）。**IMEに依存する best-effort** なので、拾えなくても手入力を妨げないこと。ふりがな欄を人が触ったら自動入力は止める
- メールアドレスは**任意。ただし入力があれば形式を確かめる**（クライアント `App.isValidEmail` / サーバー `isValidEmail_`。**同じ正規表現を両方に置いてある**）。判定はわざと緩く、電話番号や `@` の打ち忘れのような「送っても届かない形」だけを止める
- 性別と年齢は**必須**。性別には「回答しない」を用意し、答えたくない人も先へ進めるようにする。選択肢は `common_script.html` の `GENDER_OPTIONS` から組み立て、フォームのHTMLに直接書かない（サーバーの `GENDER_VALUES` と食い違わせないため）
- 性別の初期値は**空（「選択してください」）にする。** 既定で「男性」が入っていると、選んでいないのか選んだ結果なのかを本人も見分けられず、そのまま送信されてしまう
- **日付ブロックの中に時間帯の行が並ぶ入れ子**。日ごとに都合が違うのが普通なので、日付を1つ選んで終わりにはしない

```
┌─ 8月10日(土) ──────┐
│ 10:00 〜 12:00   × │
│ 15:00 〜 17:00   × │
│ [＋ 時間帯を追加]          │
└────────────────────┘
[＋ 日付を追加]
```

- **日付を足したときは直前の日の時間帯をそのまま入れる。** 同じ時間で通う人が大半なので、既定で埋まっていれば日付を足すだけで済む。日付も「最後の日の翌日」を入れておく
- 時刻はプルダウンではなく**時・分の直接入力**
- 初期値は `_config` の `entry_default_start`〜`entry_default_end`。**`day_start`〜`day_end`（一日の全体範囲）は使わない。** そのまま出すと申告として広すぎる
- 日をまたぐ申告は24時超で入力させる（`22:00`〜`26:00`）。5.1 の表記をそのまま使う

> **「終日OK」ボタンは廃止した。** 一日の全体範囲をそのまま申告として送らせると、実際には入れない時間まで可用として集まる。初期値（`entry_default_*`）から本人に直させる。
- 送信後は「登録できました」と入力内容のサマリを表示する（控えを画面で確認できる）
- 同じ人が再送信した場合、既存の名前候補をサジェストするが**選択は強制しない**（表記ゆれは許容する方針）
- 管理者用の代理入力も同じフォームを流用し、種別（volunteer/staff）を選べるようにする

### 4.4 未充足枠一覧（取り下げ）

> **作らないことにした。** 枠を廃止して割り当てと統合した結果、「必要だがまだ誰もいない」をデータとして持てなくなり、不足を機械的に出せない（3 `assignments` / 6.4）。
>
> 必要になったら、役割ごとの必要時間帯を持つテーブルを足すところから設計し直すこと。

### 4.5 印刷ビュー（print）

`?view=print&d=YYYY-MM-DD`。配置表の画面（`&view=board` / `&view=admin`）の「PDF」ボタンから別のタブで開く。

- **用紙はA3・横。** 上から「役割ごと」、改ページして「人ごと」。順序と並びは画面と同じ
- **横は必ず1枚に収める。ページを分けるのは縦だけ**（要件）
- 画面と同じタイムライン形式にする（A3横なら1日分が横幅に収まるため）
- ブラウザの印刷機能をそのまま使う。送信先を「PDFに保存」にすると1つのPDFになる
- 性別・年齢を載せる（サーバーへは `getDayBoard(token, date, true)` で問い合わせる）

> **表形式にするつもりだったが、A3横にした時点でやめた。** A4を前提に「タイムラインは紙では読みにくい」と決めていたが、A3横では1日分が横幅に収まり、画面と同じ形のまま読める。画面と紙で形が違うと、両方を突き合わせる作業（紙に赤を入れて画面で直す）が難しくなる。

#### ページの切り方

**どこで切るかは JavaScript が実測して決める**（`print_script.html` の `layoutSection` / `fitsInPage`）。行を1つ置くたびに下端を測り、はみ出したら取り除いて次の紙へ回す。

CSS の `break-inside` には頼らない。**行の高さが段数（同じ役割に重なった割り当ての数）で変わるため、どこで切られるか予測できない。** 時間軸の目盛りが出ないページができると、その紙は読めなくなる。

- 時間軸の目盛りは**すべてのページの先頭に置く**
- 凡例・件数はそのセクションの1枚目にだけ置く
- 用紙の高さは印刷可能領域より 2mm 小さく取る（丸め誤差で空白ページが出るのを防ぐ）

#### 白黒印刷（会場のプリンタは白黒であることが多い）

**色は補助にとどめ、色が消えても同じことが読み取れる状態を保つ。**

| 対象 | 白黒での問題 | 対応 |
|---|---|---|
| 役割ごとの色分け（`--tint-*`） | 淡い色は同じ濃さに潰れる | 行の区切り線を画面より濃くし、役割名で見分ける |
| 割り当ての帯 | 淡い色の上に淡い帯が乗ると輪郭が消える | 帯を**白地＋濃い枠線**にする |
| 申告外（赤） | 赤と青が同じ濃さになる | **明暗を逆にする**（白地＋太枠＋濃い文字）＋「⚠」の文字＋氏名欄の「申告外 N件」 |
| 前日からの繰り越し | 破線は白黒でも残る | 破線のまま。加えて「前日から」と文字で書く |

印刷ビューには「白黒で確認」（`body.mono`）を置いた。**紙面に手を入れたら、ここで色を落として読めるか必ず確かめること。**

## 5. データの扱い

### 5.1 日付と時刻は文字列で持つ

**スプレッドシートのセルを日付型/時刻型で扱わないこと。** GASとシートのタイムゾーン差でずれる事故が頻発する。

- 日付: `YYYY-MM-DD` の文字列
- 時刻: `HH:mm` の文字列（**`00:00`〜`47:59`**。下記）
- シート側は該当列を「書式なしテキスト」に設定する

比較・計算はすべて分単位の数値に変換して行う。

#### 24時以降は翌日を指す

**時刻は24時間制の延長で持つ。** `25:00` は「翌日の1時」。日をまたぐ割り当てを**1本で**表せるようにするためで、`22:00`〜`26:00` は「夜10時から翌朝2時まで」の1区間になる。

- **`date` 列は動かさない。** 日をまたいでも、その割り当ては開始日の行として1行で持つ
- 上限は **`47:59`（＝翌日の23:59）**。翌々日まで許すと「どの日の割り当てなのか」が人にもコードにも追えなくなるため。`48:00` 以上は `isValidTimeStr_` が弾く
- **保存値は変換しない。** シートには `25:00` がそのまま入る
- **画面とエラー文には `翌01:00` の形で出す**（サーバー: `toDisplayTime_` / クライアント: `App.timeLabel`）。人が読む文字列を作るときだけ通すこと
- 入力欄は時が 0〜47。打った数字はそのまま残る（`25` と打てば `25`）

この表記なら、`overlaps_` や `mergeRanges_` といった区間の計算に日付の概念を持ち込まずに済む。**日をまたぐたびに日付を繰り上げる実装にしないこと。** 区間判定が一気に壊れる。

#### 翌日の画面には「前日からの続き」を写して出す

`date` を動かさない以上、8/10 の `22:00`〜`26:00` は 8/10 の1行でしかない。そのままだと **8/11 の画面には何も出ず、「翌朝2時まで人がいる」ことが分からない。**

そこで `getDayBoard` が、**前日の行のうち24時を越える分を、その日のタイムラインへ写して返す**（`readAssignmentsByDate_` / `readAvailabilityByDate_`）。

- 時刻を24時間ぶん戻す（`26:00` → `02:00`）。`carried_from` に元の日付、`origin_start_time` / `origin_end_time` に元の時刻を入れる
- **シートには何も書かない。** 画面の上だけで前日の続きを見せる
- **割り当てだけでなく可用性も同じように写す。** 片方だけ写すと、申告の中に入っているはずの割り当てが「申告外」と誤警告される
- 画面では左端を破線にして淡く描き、**この画面では編集させない**（`slot--carried`）。画面の時刻（`02:00`）と保存値（`26:00`）が違うため、ここで保存すると前日の割り当てが早朝の時刻で上書きされる。タップしたら元の日へ移動させる

**表示範囲（`day_start`〜`day_end`）の外なら、写しても見えない。** 早朝を含めたい日は `day_start` を `00:00` に寄せること。

#### 衝突判定は前後の日も見る

同じ理由で、`checkConflicts_` は日付の完全一致で探してはいけない（`readDayTimeline_`）。

```
8/10 A地点 22:00–26:00  鈴木
8/11 A地点 00:00–02:00  高橋   ← 別の日なので「重ならない」と判定されると、同じ役割に2人立つ
```

前日の行は24時間ぶん戻し、翌日の行は24時間ぶん進めて、その日の物差しに揃えてから重なりを見る。

```javascript
function toMinutes_(hhmm) {
  const [h, m] = hhmm.split(':').map(Number);
  return h * 60 + m;
}

function toHHMM_(minutes) {
  const h = String(Math.floor(minutes / 60)).padStart(2, '0');
  const m = String(minutes % 60).padStart(2, '0');
  return `${h}:${m}`;
}
```

### 5.2 データ量への対処

`assignments` は日々増える。年度ごとにシートを分けるか、過去分をアーカイブシートへ退避する仕組みを**最初から用意しておく**（後付けは難しい）。

読み込みは常に日付で絞る。`getDataRange().getValues()` で全件読んでからフィルタする実装は、当面は許容するが、行数が数千を超えたらシート分割に切り替える。

## 6. 重要ロジック

**本ツールの中核。ここを間違えると成立しない。** 実装したら必ず動作確認すること。

### 6.1 区間の重なり判定

```javascript
// [aStart, aEnd) と [bStart, bEnd) が重なるか（すべて分単位の数値）
function overlaps_(aStart, aEnd, bStart, bEnd) {
  return aStart < bEnd && bStart < aEnd;
}
```

境界が接するだけ（10:00-11:00 と 11:00-12:00）は**重ならない**扱いとする。連続する時間帯に同じ人を続けて入れられなくなるため、ここは半開区間で扱う。

### 6.2 完全包含の判定

その時間帯を最初から最後まで担当できるかの判定。

```javascript
function covers_(avStart, avEnd, slotStart, slotEnd) {
  return avStart <= slotStart && slotEnd <= avEnd;
}
```

### 6.3 候補者の抽出

**人を選ぶ画面（4.2.1）に出すのは、その日に入れる時間帯がある人だけ。**

ボランティアは申告した日にだけ出る。**職員は毎日出る**（申告が無ければサーバーが既定の勤務時間帯を補うため。3章 `availability` を参照）。

時間はまだ決まっていないので、ダブルブッキングの除外はここではできない。重なりは時間を決める画面で注意書きとして知らせ、**最終的にはサーバー側が弾く**（6.6）。

並べ替えは次の順。

1. `type=volunteer` を先、`type=staff` を後（**ボランティア優先が画面から分かるように**）
2. 同種別内では、当日の割り当て合計分数の昇順（「あと誰に頼めるか」を探す画面なので、余裕のある人が上）
3. `kana`（なければ `name`）

名寄せ元（`merged_into` あり）は出さない。統合先が出る。

計算は**クライアント側に閉じている**。`getDayBoard` が返したその日のデータだけで求め、パネルを開くたびにサーバーへ問い合わせない（CLAUDE.md 開発ルール）。ただし保存時はサーバー側が同じ検証をやり直す。

### 6.4 充足判定（取り下げ） / 6.5 整合性警告（取り下げ）

> **どちらも作らない。** 枠の廃止にともない、判定の土台が無くなった。
>
> - **充足判定** … 「この枠に何人必要か」を持てないため、足りているかを機械的に言えない
> - **整合性警告**（`no_availability` など） … 申告外の割り当ては画面上で赤く描いて示す（4.1.1）。`getDayBoard` の `warnings[]` は返却形ごと廃止した
>
> 申告の外に割り当てられている区間を赤で描くことだけは残っている。**これは判定結果ではなく、その場の見た目**であり、クライアント側で計算している。

### 6.6 1つの役割の同じ時間に入るのは1人まで

**役割と時間が決まれば、そこに立つ人は1人。** 同じ時間に複数人を置きたい場合は、**役割を複数作って運用する**（「A地点1」「A地点2」のように分ける）。

```
A地点1  10:00–12:00  鈴木
A地点2  10:00–12:00  高橋     ← 2人目は役割を分けて表す
```

判定は**同じ役割で時間が重なるかどうか**で行う（`checkConflicts_`）。枠が無くなったので、枠をまたいだ抜け道もない。

- サーバー: 同じ日・同じ役割で時間が重なる割り当てが既にあれば弾く。**ロックの内側で読み直してから判定する**（クライアントの候補計算は画面を開いた時点のデータに基づくため、これが無いと二重に入る）
- 本人が既に入っている場合と、別の人が入っている場合で文言を分ける。「埋まっている」とだけ言われても、画面を更新すべきなのか自分の操作が重複したのかが分からない
- 接するだけ（10:00–12:00 と 12:00–14:00）は重ならない（6.1）。同じ役割に続けて別の人を入れられる
- **人数はどこにも出さない**（常に0か1なので数える意味がない）

配置表では段組み（レーン）を残してある。**シートを直接編集すれば重なりを作れてしまうため、それを画面から隠さない。** 隠すと、なぜ登録できないのかが分からなくなる。

## 7. API（`google.script.run` から呼ぶ公開関数）

呼び出し粒度は粗く。戻り値は `{ ok, data }` / `{ ok, error }` に統一。

**すべての関数が第1引数に閲覧トークンを取る。** 記名は行わないため、操作者名は受け取らない。

| 関数 | 引数 | 戻り値 |
|---|---|---|
| `getBootstrap(token)` | 閲覧トークン | `{ config, places }` |
| `getDayBoard(token, date, admin)` | `admin` は性別・年齢を返すかどうかだけを切り替える（保護ではない） | `{ date, assignments, availability, people }` |
| `assign(token, payload)` | date/役割/開始/終了/人/メモ。**割り当てを作る唯一の関数** | `{ assignment }` |
| `saveAssignment(token, payload)` | id/役割/開始/終了/メモ。**人と日付は変えない** | `{ assignment }` |
| `unassign(token, assignmentId)` | | `{ removed, already }` |
| `submitAvailability(token, payload)` | 名前/ふりがな/連絡先/性別/年齢/種別/`days`（日付と時間帯の配列） | `{ personId, name, kana, gender, age, type, days, isNewPerson }` |
| `savePlaces(token, places)` | | `{ places }` |

> **廃止した関数**: `assignToNewSlot`（`assign` に統合）/ `saveSlots` / `generateSlots` / `copySlots`（枠ごと廃止）/ `getShortageList`（6.4 取り下げ）。

### 排他制御

- `submitAvailability` … **Lock必須。** 応募が集中する時間帯があるため
  - **複数日を1回の呼び出しで受ける。** 日ごとに送らせると3日分の応募で3往復になり、応募が集中したとき Lock の待ちが積み上がる
  - 同じ日が2ブロック送られてきたら1日にまとめる（申告を取りこぼさない）
- `assign` / `saveAssignment` … **Lock必須。** ロック内で同日の割り当てを読み直し、**同じ役割・重なる時間に先客がいないか**（6.6）と**同じ人が同時刻に別の役割へ入っていないか**を再検証してから書き込む
  - 可用性が時間帯を覆っていない場合は弾かない（6.5 の考え方と同じ扱い）
  - `saveAssignment` は自分自身を衝突相手から除く
- その他の書き込み関数もすべてLockで保護する（`gas.md` 5.2）

### `getDayBoard` の返却範囲

その日の描画と候補者計算に必要な**すべて**を1回で返す。

- `assignments`: 指定日の全割り当て（役割・時間帯・人を含む1行完結）
- `availability`: 指定日の全件（本人が申告した行＋**申告の無い職員に補った既定の勤務時間帯**。補った分には `virtual: true` が付き、シートには存在しない）
- `people`: 上記に登場する人＋`is_recurring` の人

`warnings[]` は返さない（6.5 取り下げ）。

**`contact` と `note` は誰にも返さない**（2章の「連絡先の非公開」）。氏名は `public_name_style` に従って加工する。

`people` の `gender` / `age` は `admin=true` のときだけ含める（2章の「性別・年齢の扱い」）。**列を追加する前に登録された人は未入力なので、値が無い前提で描くこと。**

## 8. セットアップ

`setup()` 関数を用意し、初回実行で以下を行う。

1. 必要なシートを作成し、ヘッダー行を書き込む
2. `_config` に既定値を投入し、`view_token` をランダム生成する
3. 日付・時刻列の書式を「書式なしテキスト」に設定する
4. `_config` / `_log` を非表示にする（運用者が誤って壊さないように）
5. 生成された閲覧URLをログに出力する

合言葉の設定は不要（認証を行わないため）。URLが漏れた場合は `regenerateViewToken()` で作り直す。

### 運用関数（画面からは呼ばない）

7章のAPIとは別に、スプレッドシート側から実行する関数がある。**いずれも冒頭で `requireOwner_()` を呼び、匿名からは実行できない。**

| 関数 | 実行方法 | 内容 |
|---|---|---|
| `setup()` / `showViewUrl()` / `setWebAppUrl()` / `regenerateViewToken()` | スクリプトエディタ | 初回設定・URL管理 |
| `migrateSlots()` / `inspectMigrationOrphans()` | スクリプトエディタ | 枠廃止にともなう1回きりの移行 |
| `importStaff()` | **メニュー**「シフト管理 ▸ 職員を一括登録する」 | `staff_import` シートの取り込み |
| `prepareStaffImportSheet()` | **メニュー**「シフト管理 ▸ 一括登録シートを開く」 | 一括登録シートの用意 |

一括登録だけメニューにしているのは、**シートに書いて取り込む作業であり、スクリプトエディタを開く必然性が無い**ため。記入した画面のまま実行できるほうが間違いが少ない。メニューは `menu.js` の `onOpen`（単純トリガー）で組み立てる。

書き込みを伴うため `importStaff()` も `withLock_` を通す。
