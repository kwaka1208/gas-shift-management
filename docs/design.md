# 設計

`gas.md` の方針に準拠する。以下はその上でのプロジェクト固有の設計。

## 1. 全体構成

```
[ボランティア] ──URL/QR──▶ 可用性登録フォーム ─┐
                                              │
[管理者] ──管理URL──────▶ 配置表／割り当て画面 ─┼─▶ google.script.run
                                              │
[閲覧者] ──URL──────────▶ 配置表（読み取り）  ─┘         │
                                                        ▼
                                              GAS（api.js → service_*.js）
                                                        │
                                                        ▼
                                              スプレッドシート（1シート＝1テーブル）
```

デプロイ設定は **実行ユーザー: 自分 / アクセス: 全員（匿名ユーザーを含む）**。
利用者はGoogleアカウント不要。その代わりシートの権限は一切渡らない。

## 2. 認証設計

**認証は行わない。** 保護はURLに含まれる推測困難なトークン（`?t=xxxxx`）の1段階だけ。

| 種別 | 方式 | 用途 |
|---|---|---|
| 閲覧・管理を通じて | URLに推測困難なトークン（`?t=xxxxx`） | すべての画面・すべてのAPI |

- 閲覧トークンは `_config` シートに保持する。
- **すべての公開関数で、読み書きを問わずサーバー側でトークンを検証する。** クライアント側の画面制御だけに頼らない。
- 漏えい時は `regenerateViewToken()` で作り直す。以前のURL・QRコードは無効になるため配り直しが必要。

### この設計で守れるもの・守れないもの

| | |
|---|---|
| 守れる | URLを知らない第三者からのアクセス |
| **守れない** | **URLを知っている人による編集・削除** |

QRコードを配った相手（＝ボランティア全員とその転送先）は、全員が枠を作成・削除できる。これは受け入れた上での判断である。

### 画面の分離（認証ではない）

閲覧用と管理用でURLを分ける。

| URL | 画面 |
|---|---|
| `?t=<token>&view=board` | 配置表（見るだけ。管理操作のボタンを出さない） |
| `?t=<token>&view=admin` | 配置表（枠の作成・割り当てができる） |

**同じ画面（`index.html`）で、`boot.admin` の真偽だけが違う。** モードの切り替えUIは持たない。

**これは保護ではない。** トークンは共通なので、閲覧URLを知っていれば `view=admin` を足すだけで管理画面を開ける。サーバー側も閲覧トークンしか見ない。**誤操作を防ぐための画面の分離**であり、それ以上の意味を持たせないこと。

### 誰が変更したかの記録

**記名は行わない。** 管理URLを開けば誰でも操作できるため、操作者を特定する手段が無い。`_log` の操作者列には固定値（`LOG_OPERATOR`）を入れ、記名していないことが分かるようにする。

> 以前は管理モードに入る際に操作者名を選ばせていたが、モード切り替えの廃止に伴ってやめた。誰が変更したかを追う必要が出たら、URLごとにトークンを分ける設計から検討し直すこと。

### 連絡先の非公開

上記のとおり管理者だけを識別する手段が無いため、**`people.contact` と `people.note` はどの画面にも返さない。** サーバー側（`toPublicPerson_`）で落とす。連絡先が必要な場面では、管理者がスプレッドシートの `people` シートを直接参照する。

## 3. シート定義

1シート＝1テーブル。1行目がヘッダー（列ID）、2行目以降がデータ。
全テーブルに `id`（`Utilities.getUuid()`）、`created_at`、`updated_at` を持たせる。**行番号をIDとして使わない。**

### `places`

| 列 | 型 | 説明 |
|---|---|---|
| id | string | UUID |
| name | string | 場所名 |
| sort_order | number | 配置表での表示順 |
| active | boolean | 廃止した場所は false（行は消さない） |

### `slot_templates`

週次パターンの定義。ここから `slots` を生成する。

| 列 | 型 | 説明 |
|---|---|---|
| id | string | UUID |
| template_name | string | テンプレート名（複数パターンを持てるように） |
| day_of_week | number | 0=日 〜 6=土 |
| place_id | string | |
| start_time | string | `HH:mm` |
| end_time | string | `HH:mm` |
| required_count | number | 必要人数 |
| staff_required | number | 職員最低人数（0 なら不問） |

### `slots`

| 列 | 型 | 説明 |
|---|---|---|
| id | string | UUID |
| date | string | `YYYY-MM-DD` |
| place_id | string | |
| start_time | string | `HH:mm`（10分単位） |
| end_time | string | `HH:mm`（10分単位） |
| required_count | number | **画面では扱わない。** `_config` の既定値が入る（人数は場所単位で運用する方針） |
| staff_required | number | 同上（現在は常に0） |
| note | string | 任意メモ |

### `people`

**使い捨て前提のテーブル。** 単発参加者の重複・表記ゆれは許容する。継続参加者のみ管理者が手動で名寄せする。

| 列 | 型 | 説明 |
|---|---|---|
| id | string | UUID |
| name | string | 表示名 |
| kana | string | 並べ替え用（任意） |
| type | string | `volunteer` / `staff` |
| contact | string | 連絡先。**公開ビューには絶対に出さない** |
| is_recurring | boolean | 継続参加者フラグ。true の人だけ次回以降の候補に自動で出す |
| merged_into | string | 名寄せ時に統合先の person_id を記録（行は消さない） |
| note | string | |

### `availability`

| 列 | 型 | 説明 |
|---|---|---|
| id | string | UUID |
| person_id | string | |
| date | string | `YYYY-MM-DD` |
| start_time | string | `HH:mm` |
| end_time | string | `HH:mm` |

1人が同じ日に複数行を持てる。職員は行を持たず、`_config` の既定勤務時間帯を可用とみなす（`getDayBoard` 内で仮想的に補う）。

### `assignments`

| 列 | 型 | 説明 |
|---|---|---|
| id | string | UUID |
| slot_id | string | |
| person_id | string | |
| assigned_by | string | 操作者名。記名は行わないため固定値が入る（2 参照） |

### `_config`

`key` / `value` の2列。運用者が触ってよいシート。

| key | 例 | 説明 |
|---|---|---|
| view_token | `a8f3...` | 閲覧URLのトークン |
| day_start | `10:00` | 配置表タイムラインの左端 |
| day_end | `17:00` | 右端 |
| slot_unit_minutes | `10` | 時刻選択の刻み |
| staff_default_start | `10:00` | 職員の既定可用開始 |
| staff_default_end | `17:00` | 職員の既定可用終了 |
| default_slot_start | `10:00` | 既定の枠の開始（枠が無い場所に仮想表示。空にすると出さない） |
| default_slot_end | `17:00` | 同、終了 |
| default_slot_required | `1` | 既定の枠の必要人数 |
| public_name_style | `full` / `family` | 公開ビューでの氏名表示粒度 |

### `_log`

`timestamp` / `operator` / `action` / `target_id` / `detail`。運用者がシートで直接見られることが重要。

## 4. 画面

すべて `doGet(e)` からパラメータで振り分ける。ルーティングは薄く保つ。

| URL | 画面 | 認証 |
|---|---|---|
| `?t=<token>&view=board&d=YYYY-MM-DD` | 配置表・閲覧用（既定。日付省略時は当日） | 閲覧トークン |
| `?t=<token>&view=admin&d=YYYY-MM-DD` | 配置表・管理用 | 閲覧トークン |
| `?t=<token>&view=entry` | 可用性登録フォーム | 閲覧トークン |
| `?t=<token>&view=print&d=YYYY-MM-DD` | 印刷用配置表 | 閲覧トークン |

board と admin は同じテンプレート（`index.html`）を使い、`boot.admin` で出し分ける（2 の「画面の分離」）。

### 4.1 配置表（board）

- 縦軸=場所（`sort_order` 順）、横軸=時間（`day_start`〜`day_end`）のタイムライン
- **10分刻みは目盛りとして描くだけ。** 枠のブロックは開始・終了時刻から幅を計算して配置する。10分刻みのセルを敷き詰める実装にしないこと（列数が爆発し、DOMもデータも破綻する）
- 各ブロックに「時間 / 割り当て人数 / 割り当て済みの氏名」を表示。**必要人数は画面に出さない**（人数は場所単位で運用する方針。`slots.required_count` は列としては残すが、画面からは編集しない）
- 色分け:
  - 赤: ボランティアだけでは不足
  - 黄: 職員込みで充足（＝職員の穴埋めが入っている）
  - 緑: ボランティアだけで充足
  - 警告アイコン: 職員必須なのに未配置／可用性のない割り当てがある
- 日付切り替え（前日・翌日・カレンダー選択）
- 管理URLでは各ブロックがタップ可能になり、割り当てパネルが開く
- 画面の下半分に「人ごと」の一覧を並べる（4.1.1）
- **モードの切り替えは持たない。** 空いているところをタップすれば人を選ぶ画面、枠をタップすれば割り当てパネル。枠そのものの編集は割り当てパネルの「この枠を編集する」から入る

### 4.2 枠のパネル（管理URL）

枠をタップすると開くモーダル。**上に枠そのものの編集、下に人の出し入れ**を並べる。

枠をタップしたらまず「場所と時間を直せる」ことが分かるよう、編集欄を先頭に置く。人の追加・解除も同じパネルで完結させ、画面を行き来させない。

```
[ A地点 10:00-11:30 ]

場所  [A地点 ▾]
時間  [10:00] 〜 [11:30]
メモ  [            ]
   [この枠を削除] [枠を保存]
─────────────────────
割り当て済み (2)
  ● 田中さん（ボランティア）        [解除]
  ● 佐藤さん（職員）                [解除]

割り当て可能 (5)
  ボランティア
    ○ 鈴木さん   本日の割当 0分
    ○ 高橋さん   本日の割当 60分
  職員
    ○ 伊藤さん   本日の割当 120分

一部の時間のみ可用 (2)          ← 折りたたみ、控えめに表示
    ○ 渡辺さん   10:40-11:30 のみ可用

[ 時間を指定して入れる ]        ← 4.2.1
[ この枠を編集する ]            ← 枠の場所・時間・必要人数の変更と削除
```

- 候補者の算出は**クライアント側で行う**（`getDayBoard` が返したその日の全データから計算）。サーバー往復を発生させない
- 割り当て／解除は都度サーバーに送るが、**画面は先に更新し、失敗時にロールバックする**（楽観的更新）。同時編集を考慮しない前提なのでこれで足りる
- 二重送信防止のため、送信中はボタンを無効化する
- **必要人数の入力は持たない**（4.1 参照）。保存時は既存の値をそのまま送り返す

### 4.2.1 枠の作られ方は2通りある

**普段の運用では枠を先に作らない。** 場所の空いているところをタップし、人と時間を選ぶと、その時間の枠ができて人が入る。

```
[ 場所の空きをタップ ]
      ↓
人を選ぶ          ← その日に申告のある人を全員表示（ボランティア→職員、当日の割当が少ない順）
      ↓
時間を決める      ← 初期値はその人が申告した時間帯
      ↓
枠ができて、その人が入る
```

必要人数は入力させない。`slots.required_count` には `_config` の `default_slot_required` が入る。

順番は**人 → 時間**。先に人を選べば、申告された時間帯をそのまま初期値にできる（「来られる時間をそのまま入れる」運用に合う）。

**「まだ誰も入っていない枠」を作れるのは「既定の枠」だけ**であり、不足の可視化（4.4 / 6.4）はこの経路に依存する。

`generateSlots`（週テンプレート展開）と `copySlots`（前日・前週コピー）はAPIとして残しているが、**画面に入口は無い**。運用が固まって必要になったら画面を足すこと。

既存の枠に対しても、枠の時間とは違う時間で人を入れられる（「時間を指定して入れる」／部分可用者の行）。この場合は**指定した時間の枠が別にできる**。割り当て自体は時間を持たない。

同じ日付・場所・開始・終了の枠が既にあれば、新しく作らずにその枠を使う。同じ時間の枠が増えると配置表が段だらけになって読めなくなるため。

**誰もいなくなった枠は自動で消さない。** 割り当てをやり直すたびに枠が消えたり生えたりすると、先に立てた計画（必要人数）が失われる。

### 4.2.2 既定の枠（仮想）

**枠を1つも作っていない場所には、`_config` の既定時間帯の枠が最初から表示される。** 破線で描き、シートには行が無いことを示す。人を入れた時点で `assignToNewSlot` が実体を作る。

```
_config: default_slot_start / default_slot_end / default_slot_required
```

- `getDayBoard` が `appendDefaultSlots_` で補う。**読み取りAPIはシートに書き込まない。** 閲覧者が日付を送るたびに空の枠が実体化していくのを防ぐ（職員の既定可用時間帯を補う `appendStaffDefaultAvailability_` と同じ考え方）
- 仮想の枠は `virtual: true` と `id: 'virtual:<place_id>:<date>'` を持つ
- **既に枠のある場所には出さない。** 運用が始まっている場所に空の枠を割り込ませない
- `default_slot_start` / `default_slot_end` のどちらかを空にすると、この補完は止まる

クライアント側の注意:

- `saveSlots` へ送る一覧からは**必ず仮想の枠を除く**（`realSlots()`）。混ぜると「存在しない枠です」で拒否される
- 仮想の枠に `assign` は使えない。人を選ぶ画面（4.2.1）へ進ませる
- 実体ができたら、その場所の仮想の枠は画面から取り除く（二重に描かれるため）

**誰も入っていない枠を先に残したいときは、実体にする必要がある**（管理画面の「既定の枠」）。不足の可視化（4.4 / 6.4）は実体のある枠にしか効かない。

### 4.1.1 人ごとの一覧（配置表の下半分）

配置表は**同じ日を2つの見方で縦に並べる**。切り替えではなく上下に並べるのは、片方を見ながらもう片方を直す作業だから。

```
場所ごと   ← 枠が埋まっているか
─────────
人ごと     ← 誰がまだ空いているか
```

下半分は縦が人、横が時間。

```
             10:00      12:00      14:00      16:00
鈴木  空き     ░░░░░░░░░░░░░░░░░░░  ░░░░░░░░░░░░░
高橋  2時間    ░░░░░░░░░░[A地点]░░░░░░░░░░░░░░░░░░
伊藤(職)      ┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈
             ░ 入れる時間   ■ 割り当て済み   ┈ 職員の既定勤務時間帯
```

- **可用の帯の上に、割り当ての帯を重ねて描く。** 申告のうちどこが埋まってどこが空いているかを、目で追わずに分かるようにするため
- 並び順は**当日の割り当てが少ない順**、同数ならボランティア先、次に `kana`。「あと誰に頼めるか」を探す画面なので、余裕のある人が上に来る
- 出すのは**その日に関わりのある人だけ**（申告した人、または割り当てのある人）。継続参加者でも申告が無ければ出さない。空行が並ぶと目的が埋もれる
- 申告の外に割り当てられている区間は赤で描く（6.5 `no_availability` の予告）
- `people` に無い `person_id` の割り当ても「(不明な人)」として行を作る。**割り当てを画面から消さない**

- 管理URLでは、**割り当ての帯をタップすると解除できる**。帯は小さく指が触れただけで人が消えると気付けないため、**ここだけは確認を挟む**（割り当てパネルの解除ボタンは即時）

データは `getDayBoard` 1回で足りるため、**この一覧のために新しいAPIは作らない。**

実装上の注意:

- **イベント登録は `#board` / `#people` の中だけを探すこと。** 人ごとの一覧も同じ骨組み（`.board__lanes`）を使っているため、`document` 全体から拾うと人の行をタップしたときに枠の作成画面が開く
- 割り当て・解除のあとは**両方を描き直す**（`refreshAssignView`）。片方だけだと数字が食い違う

### 4.3 可用性登録フォーム（entry）

ボランティアがQRコードから開く。**この画面のわかりやすさが参加率に直結する。**

- 入力項目: 名前 / 連絡先 / **入れる日と時間帯（複数日）**
- **日付ブロックの中に時間帯の行が並ぶ入れ子**。日ごとに都合が違うのが普通なので、日付を1つ選んで終わりにはしない

```
┌─ 8月10日(土) ──────┐
│ 10:00 〜 12:00   × │
│ 15:00 〜 17:00   × │
│ [＋ 時間帯を追加] [終日OK] │
└────────────────────┘
[＋ 日付を追加]
```

- **日付を足したときは直前の日の時間帯をそのまま入れる。** 同じ時間で通う人が大半なので、既定で埋まっていれば日付を足すだけで済む。日付も「最後の日の翌日」を入れておく
- 時刻はプルダウンではなく**時・分の直接入力**
- 「終日OK」ボタンで `day_start`〜`day_end` を一括入力（日付ブロックごと）
- 送信後は「登録できました」と入力内容のサマリを表示する（控えを画面で確認できる）
- 同じ人が再送信した場合、既存の名前候補をサジェストするが**選択は強制しない**（表記ゆれは許容する方針）
- 管理者用の代理入力も同じフォームを流用し、種別（volunteer/staff）を選べるようにする

### 4.4 未充足枠一覧（管理URL）

職員配置のフェーズで使う画面。ボランティア割り当て完了後、残った枠だけを一覧表示する。

- 日付範囲を指定して、`ボランティア数 < required_count` の枠を列挙
- 各行から直接割り当てパネルを開ける
- これがあるだけで職員配置の作業が一気に片付く

### 4.5 印刷ビュー（print）

- 1日1ページ。場所×時間の表形式（タイムラインではなく表の方が紙では読みやすい）
- 色に頼らず、不足枠は文字（「不足2名」）でも示す
- ブラウザの印刷機能をそのまま使う（`@media print` で調整）

## 5. データの扱い

### 5.1 日付と時刻は文字列で持つ

**スプレッドシートのセルを日付型/時刻型で扱わないこと。** GASとシートのタイムゾーン差でずれる事故が頻発する。

- 日付: `YYYY-MM-DD` の文字列
- 時刻: `HH:mm` の文字列
- シート側は該当列を「書式なしテキスト」に設定する

比較・計算はすべて分単位の数値に変換して行う。

```javascript
function toMinutes_(hhmm) {
  const [h, m] = hhmm.split(':').map(Number);
  return h * 60 + m;
}

function toHHMM_(minutes) {
  const h = String(Math.floor(minutes / 60)).padStart(2, '0');
  const m = String(minutes % 60).padStart(2, '0');
  return `${h}:${m}`;
}
```

### 5.2 データ量への対処

`slots` と `assignments` は日々増える。年度ごとにシートを分けるか、過去分をアーカイブシートへ退避する仕組みを**最初から用意しておく**（後付けは難しい）。

読み込みは常に日付で絞る。`getDataRange().getValues()` で全件読んでからフィルタする実装は、当面は許容するが、行数が数千を超えたらシート分割に切り替える。

## 6. 重要ロジック

**本ツールの中核。ここを間違えると成立しない。** 実装したら必ず動作確認すること。

### 6.1 区間の重なり判定

```javascript
// [aStart, aEnd) と [bStart, bEnd) が重なるか（すべて分単位の数値）
function overlaps_(aStart, aEnd, bStart, bEnd) {
  return aStart < bEnd && bStart < aEnd;
}
```

境界が接するだけ（10:00-11:00 と 11:00-12:00）は**重ならない**扱いとする。連続する枠に同じ人を入れられなくなるため、ここは半開区間で扱う。

### 6.2 完全包含の判定

枠を最初から最後まで担当できるかの判定。

```javascript
function covers_(avStart, avEnd, slotStart, slotEnd) {
  return avStart <= slotStart && slotEnd <= avEnd;
}
```

### 6.3 候補者の抽出

ある枠 `slot` に対して:

1. `availability` から、同日かつ `covers_` が真の人を集める → **完全候補**
2. `availability` から、同日かつ `overlaps_` が真だが `covers_` が偽の人を集める → **部分候補**（別セクションに控えめに表示）
3. 職員は `availability` の行がなければ `_config` の既定勤務時間帯を可用とみなす
4. 上記から、**同日の他の割り当てと `overlaps_` が真になる人を除外**（ダブルブッキング防止）。ただしその枠自身への割り当ては「割り当て済み」として別扱い
5. 並べ替え: `type=volunteer` を先、`type=staff` を後。同種別内では当日の割り当て合計分数の昇順、次に `kana`（なければ `name`）

複数の可用性行を持つ人がいるため、1と2は**行単位ではなく人単位に集約**してから判定すること。

### 6.4 充足判定

```
volunteer_count = その枠の割り当てのうち type=volunteer の数
staff_count     = その枠の割り当てのうち type=staff の数

status =
  volunteer_count >= required_count                    → 'full_volunteer'  (緑)
  volunteer_count + staff_count >= required_count      → 'full_with_staff' (黄)
  それ以外                                              → 'short'           (赤)

warn_staff = staff_required > 0 && staff_count < staff_required
```

**ボランティアだけの充足と職員込みの充足を必ず分けて保持すること。** 1つの数値にまとめない。運用が2フェーズ（ボランティア割り当て→職員穴埋め）に分かれているため、どちらの作業をしているのかが画面から分からなくなる。

### 6.5 整合性警告

`getDayBoard` の応答に `warnings[]` として含める。

| 種別 | 条件 |
|---|---|
| `no_availability` | 割り当て済みだが、その人の可用性が枠を覆っていない（後から取り下げた等） |
| `double_booked` | 同一人物が同日の重なる枠に複数割り当てられている |
| `staff_missing` | `staff_required > 0` かつ職員が不足 |

**警告は表示のみ。自動で割り当てを削除しないこと。**

## 7. API（`google.script.run` から呼ぶ公開関数）

呼び出し粒度は粗く。戻り値は `{ ok, data }` / `{ ok, error }` に統一。

**すべての関数が第1引数に閲覧トークンを取る。** 記名は行わないため、操作者名は受け取らない。

| 関数 | 引数 | 戻り値 |
|---|---|---|
| `getBootstrap(token)` | 閲覧トークン | `{ config, places, templateNames }` |
| `getDayBoard(token, date)` | | `{ slots, assignments, people, availability, warnings }` |
| `assign(token, slotId, personId)` | 既存の枠へ入れる | `{ assignment }` |
| `assignToNewSlot(token, payload)` | 日付/場所/開始/終了/人。枠が無ければ作って入れる | `{ slot, slotCreated, assignment }` |
| `unassign(token, assignmentId)` | | `{ removed: true }` |
| `submitAvailability(token, payload)` | 名前/連絡先/種別/`days`（日付と時間帯の配列） | `{ personId, name, type, days, isNewPerson }` |
| `savePlaces(token, places)` | | `{ places }` |
| `saveSlots(token, date, slots)` | 1日分をまとめて保存 | `{ slots }` |
| `generateSlots(token, templateName, fromDate, toDate)` | | `{ created, skipped }` |
| `copySlots(token, fromDate, toDate, dayCount)` | `dayCount` は 1（前日）/ 7（前週） | `{ created, skipped }` |
| `getShortageList(token, fromDate, toDate)` | | `{ slots }` |
| `savePerson(token, person)` | 職員登録・名寄せ | `{ person }` |

### 排他制御

- `submitAvailability` … **Lock必須。** 応募が集中する時間帯があるため
  - **複数日を1回の呼び出しで受ける。** 日ごとに送らせると3日分の応募で3往復になり、応募が集中したとき Lock の待ちが積み上がる
  - 同じ日が2ブロック送られてきたら1日にまとめる（申告を取りこぼさない）
- `assign` … **Lock必須。** ロック内で同日の割り当てを読み直し、**同じ枠への二重割り当て**と**同日の重なる枠との衝突**を再検証してから書き込む
  - **必要人数は見ない。** 人数は場所単位で運用する方針にしたため、枠の `required_count` で人数を止めることはしない
  - 可用性が枠を覆っていない場合も弾かない（6.5 の「警告は表示のみ」と同じ扱い）
- `assignToNewSlot` … **Lock必須。** 枠の検索・作成と割り当てを同じロックの中で行う。分けると同じ時間の枠が二重にできる
- その他の書き込み関数もすべてLockで保護する（`gas.md` 5.2）

### `getDayBoard` の返却範囲

その日の描画と候補者計算に必要な**すべて**を1回で返す。

- `slots`: 指定日の全枠
- `assignments`: 指定日の全割り当て
- `people`: 上記に登場する人＋その日に可用性がある人＋`is_recurring` の人
- `availability`: 指定日の全件（職員の既定分を仮想的に補ったもの）
- `warnings`: 6.5 の判定結果

**`contact` と `note` は誰にも返さない**（本節冒頭の「連絡先の非公開」）。氏名は `public_name_style` に従って加工する。

## 8. セットアップ

`setup()` 関数を用意し、初回実行で以下を行う。

1. 必要なシートを作成し、ヘッダー行を書き込む
2. `_config` に既定値を投入し、`view_token` をランダム生成する
3. 日付・時刻列の書式を「書式なしテキスト」に設定する
4. `_config` / `_log` を非表示にする（運用者が誤って壊さないように）
5. 生成された閲覧URLをログに出力する

合言葉の設定は不要（認証を行わないため）。URLが漏れた場合は `regenerateViewToken()` で作り直す。
