# 実装ロードマップ

**フェーズ単位で実装し、各フェーズの受け入れ条件を満たしたら止めて確認を取ること。** 先のフェーズを勝手に始めない。

Phase 3 まで動けば実運用に入れる。Phase 4 は運用開始直後に必ず欲しくなるので、間を空けずに続ける。

---

## Phase 0: 基盤

- clasp プロジェクトの初期化、`appsscript.json` を含めたGit管理
- `config.js`（シート定義）、`repo_sheet.js`（バッチ読み書き）、`util.js`（時刻変換・区間判定）
- `setup()` によるシート自動生成と `_config` 初期値投入
- `service_auth.js`（閲覧トークン検証、スクリプトエディタ専用関数のガード）

**受け入れ条件**
- `setup()` を実行すると必要なシートとヘッダーが揃う
- `toMinutes_` / `toHHMM_` / `overlaps_` / `covers_` の動作を確認済み
  - 特に境界ケース: `10:00-11:00` と `11:00-12:00` が「重ならない」と判定されること
- 不正なトークンでのアクセスが弾かれる

---

## Phase 1: 枠の管理と配置表の閲覧

- 場所の登録・並べ替え
- 枠の作成・編集（10分単位の時刻選択）
- 週テンプレートからの一括生成、前日・前週コピー
- 配置表のタイムライン表示（縦=場所、横=時間）
- `getBootstrap` / `getDayBoard` / `saveSlots` / `generateSlots` / `copySlots`

**受け入れ条件**
- 週テンプレートから1週間分の枠が生成できる
- 前週の枠を翌週へコピーできる
- 配置表が場所×時間で正しく描画され、スマホでも読める
- 10分刻みのセルを敷き詰める実装になっていないこと（ブロックは開始・終了から幅計算）
- 日付を切り替えても表示が崩れない

> このフェーズが終わった時点で、まだ人は1人も割り当てられない。それで正しい。枠の運用が回らないツールは、割り当てができても使われない。

---

## Phase 2: 可用性の登録

- 可用性登録フォーム（名前・連絡先・日付・時間帯複数）
- 「終日OK」ショートカット
- 管理者による代理入力（種別の選択を含む）
- 職員の既定可用時間帯の仮想補完
- `submitAvailability`（Lock必須）

**受け入れ条件**
- QRコード経由でスマホから登録でき、送信後に控えが表示される
- 1日に複数の時間帯を登録できる
- 職員を登録すると、可用性を入力しなくても既定勤務時間帯で扱われる
- 同姓同名や表記ゆれで登録がブロックされないこと（重複は許容する方針）

---

## Phase 3: 割り当て

- 割り当てパネル（候補者リスト）
- 候補者の抽出・並べ替え（design.md 6.3）
- ダブルブッキングの除外
- 部分可用者の別セクション表示
- 割り当て・解除（楽観的更新＋失敗時ロールバック、サーバー側はLockと再検証）
- **時間を指定して入れる**（枠が無ければその場で作る。design.md 4.2.1）
- `assign` / `assignToNewSlot` / `unassign`

**受け入れ条件**
- 候補者リストでボランティアが職員より上に表示される
- 同時間帯に別の場所へ割り当て済みの人が候補に出ない
- 枠を部分的にしか満たさない人が別セクションに出て、割り当ても可能
- 当日の割り当て時間が少ない人が上に来る
- 割り当て後、配置表に即座に反映される
- 場所の空いているところをタップし、人と時間を選ぶだけで枠ができて人が入る
- 既存の枠に、枠とは違う時間で人を入れると、その時間の枠が別にできる
- サーバー側で重なり（同日の別の枠との衝突）と二重割り当てが再検証されている
- 必要人数の超過は**弾かず**、超過した事実が画面に伝わる（design.md 7 排他制御）

**ここまでで実運用に入れる。**

---

## Phase 4: 充足状況の可視化

- 枠ごとの3系統表示（必要人数 / ボランティア数 / 職員数）
- 色分け（`full_volunteer` / `full_with_staff` / `short`）
- 職員必須枠の未配置警告
- 未充足枠一覧（職員配置待ちリスト）
- 整合性警告（`no_availability` / `double_booked` / `staff_missing`）
- `getShortageList`

**受け入れ条件**
- ボランティアだけの充足と職員込みの充足が画面上で区別できる
- 未充足枠一覧から直接割り当てパネルを開ける
- 割り当て済みの人の可用性を取り消すと警告が出る。**割り当ては自動削除されない**

## Phase 5: 印刷と運用支援

- ~~印刷ビュー~~ … **実装済み**（`?view=print`。design.md 4.5）
- 人の管理画面（職員登録、`is_recurring` 設定、名寄せ）
- `_log` への操作記録
- 過去データのアーカイブ手順（年度切り替え）

**受け入れ条件**
- ~~1日分をA4で印刷でき、不足枠が文字でも判別できる~~
  → **A3横に変更した。** 1日分を「場所ごと」「人ごと」の順にA3横で印刷でき、横は必ず1枚に収まる。
  白黒で刷っても、申告外の割り当てが色以外（⚠ と白抜きの帯）で判別できる
- 継続参加者を名寄せしても過去の割り当てが壊れない（`merged_into` で参照解決）

> **不足枠の表示は作らない。** 枠の廃止にともなって取り下げた（design.md 4.4）。
> 受け入れ条件から外してある。
